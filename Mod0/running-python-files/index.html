~12–13 minutes Interactive No setup needed to read

1. A deadline that still breaks old tutorials

Python, the programming language you're learning, actually comes in two major versions: the older Python 2 and the newer Python 3. Python 2 isn't just old — it's officially retired. The team that maintains Python announced the shutoff years in advance, and on January 1, 2020, Python 2 stopped getting updates for good: no more security patches, no more bug fixes, nothing. That left a mess behind: millions of blog posts, Stack Overflow answers, and tutorials written before 2020 all say the same thing — run your file with the command python filename.py.

Here's the problem: on most computers today, typing python either does nothing at all, or quietly runs the retired Python 2 instead of the Python 3 you actually installed. Ubuntu (a common Linux system) and macOS both stopped shipping a plain python command that reliably means Python 3 — today, both only ship python3, so an old tutorial's exact command often fails outright or silently runs the wrong version.

The rest of this reading is about the right two-thirds of that picture: how python3 actually runs a saved file, and what changes when that file gets imported into something else instead of run directly.

3. What actually happens when you run a script

When you run python3 hello.py, the interpreter does the same three things every time, in order:

  1. Opens the file and reads it from the very top.
  2. Goes line by line, top to bottom, exactly once. Any code sitting outside a function runs immediately, the moment the interpreter reaches it.
  3. Any function definition it passes is stored for later — its own body doesn't run yet, only the act of defining it.

That's different from the REPL, where you control the pace one line at a time and nothing is saved once you close it. A script is the same code, saved, so it runs identically every time.

4. Why if __name__ == "__main__": exists

After trying python3 hello.py and python3 importer.py in the terminal above, you saw them print different things, even though importer.py runs hello.py's code too, through the import. Here's why. hello.py defines a function called main(), but doesn't just call it directly at the bottom of the file. It wraps that call in a check: if __name__ == "__main__":. Run hello.py directly, and Python sets its __name__ to "__main__". Import hello.py from another file instead, the way importer.py does, and Python sets its __name__ to "hello" instead, its own module name.

Without that guard, main() would fire the instant anything, anywhere, imported hello.py — even a file that only wanted to reuse one small piece of it. The guard means hello.py can be both a working script on its own and a safe, reusable module for something else, without those two jobs ever conflicting.

7. Summary & reflection

python3 is the command that's reliably worked since Python 2's real retirement in 2020. A script is code saved in a file so the interpreter can run it top to bottom the same way every time. And if __name__ == "__main__": is what keeps a file's own script behavior from firing the instant something else imports it.
