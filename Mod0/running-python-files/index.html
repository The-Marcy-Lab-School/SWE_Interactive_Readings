1. A deadline that still breaks old tutorials

The Python Software Foundation didn't quietly stop supporting Python 2 — it announced a real, fixed retirement date years in advance, and on January 1, 2020, Python 2 stopped receiving updates for good. No more security patches, no more bug fixes, nothing. That's ancient history in software terms, but it left a huge mess behind: millions of blog posts, Stack Overflow answers, and README files written before 2020 that all say the same thing: run python filename.py.

The problem is that python was never a fixed promise about which Python you'd get. Some older Linux systems still alias python to that retired Python 2 install for backward compatibility. Ubuntu 20.04 and newer ship with no python command at all by default — only python3 — specifically because Ubuntu's maintainers decided it was safer to make the command missing than to guess wrong. macOS has never shipped a python command that reliably points at Python 3 either; today it only ships python3. So typing the exact command an old tutorial gives you either does nothing, or silently runs the wrong language version.

The rest of this reading is about the right two-thirds of that picture: how python3 actually runs a saved file, and what changes when that file gets imported into something else instead of run directly.

3. What actually happens when you run a script

When you run python3 hello.py, the interpreter opens that file, reads it from the top, and executes each line in order — defining functions as it reaches them, running any code that isn't inside a function immediately, top to bottom, exactly once. That's different from the REPL, where you control the pace one line at a time and nothing is saved once you close it. A script is the same code, saved, so it runs identically every time.

4. Why if __name__ == "__main__": exists

hello.py defines a function called main(), but doesn't just call it directly at the bottom of the file — it wraps that call in a check: if __name__ == "__main__":. Here's the problem that guard solves. Python sets every file's built-in __name__ variable automatically, and what it sets it to depends entirely on how the file got run. Run hello.py directly, and Python sets its __name__ to the literal string "__main__". Import hello.py from another file instead, the way importer.py does, and Python sets its __name__ to "hello", its own module name, instead.

Without that guard, main() would fire the instant anything, anywhere, imported hello.py — even a file that only wanted to reuse one small piece of it. The guard means hello.py can be both a working script on its own and a safe, reusable module for something else, without those two jobs ever conflicting.

7. Summary & reflection

python3 is the command that's reliably worked since Python 2's real retirement in 2020. A script is code saved in a file so the interpreter can run it top to bottom the same way every time. And if __name__ == "__main__": is what keeps a file's own script behavior from firing the instant something else imports it.
