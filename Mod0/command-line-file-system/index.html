Know Where You Are

In January 2015, Valve's own Steam client for Linux quietly deleted everything a user's account could touch — game saves, personal documents, sometimes an entire backup drive that happened to be mounted at the time. Nobody hacked anyone. A single line inside Steam's own uninstall script built a delete command out of a folder path, and the script never checked whether that path still pointed at a real, specific place before running it. This reading is about the exact skill that line was missing: always knowing precisely where you are in a file system, and exactly which path (absolute or relative) a command is about to act on.

~13 minutes Interactive No setup needed to read

1. What actually happened

Steam's Linux client kept a variable called STEAMROOT pointing at the folder holding all of Steam's own files, computed each time the app launched by moving into that folder and asking the shell where it had landed. Deep in the uninstall/update logic sat a cleanup line built from that variable: something shaped like rm -rf "$STEAMROOT/"* — delete everything inside this folder. For almost everyone, that folder was a specific, harmless place.

But if the step that computed STEAMROOT ever silently failed — for a small number of users, a broken folder shortcut (a symlink) made exactly that happen — the variable came back empty instead of a real path. The delete line still ran. With STEAMROOT empty, "$STEAMROOT/"* collapsed into /*: not "everything inside one folder," but "everything inside the root of the entire file system that this user account can reach." The script had no way to tell the difference between the two, because it never confirmed the actual, current, absolute path before acting on it.

That absolute path — /home/fellow/projects/weather-app — means the same exact folder no matter what folder you happened to be sitting in when you typed it, because it's traced all the way from the root, /. A relative path like src/main.py only means something once you already know where "here" is. The Steam bug is what happens when code silently loses track of "here" and acts anyway.

3. The five commands that run everything

Everything above comes down to five commands. pwd prints your current absolute path — the honest answer to "where am I, exactly," the thing Steam's script never actually asked. ls lists what's in the current folder (or a folder you name). cd <folder> moves into a folder — a relative name moves relative to where you are, a path starting with / moves to that absolute location regardless of where you started. mkdir <name> creates a new folder inside the current one. touch <name> creates a new, empty file inside the current one.

7. Summary & reflection

A file system is a tree: one root, folders branching off it, files and more folders branching off those. pwd tells you exactly where you are in that tree right now. ls tells you what's actually around you before you act. cd moves you through it — relative to where you stand, or by absolute path regardless of where you stand. mkdir and touch build new branches and leaves. The Steam bug happened because one script skipped the first two and trusted a path it never confirmed.
