Know Where You Are

~9 minutes Interactive No setup needed to read

1. What actually happened

Steam (the video game store and launcher) once had a bug in its app for Linux computers that erased people's entire computers. Steam's uninstall process had a cleanup step: figure out exactly which folder holds Steam's own files, then delete everything inside that one folder to tidy up. For almost everyone, that step worked fine — it found the right folder, and cleanup touched only Steam's own files.

But for a small number of users, the step that figured out "which folder is this" silently failed. Instead of a real folder location, the app ended up with nothing — an empty answer to "where am I." The delete step ran anyway. And a delete command aimed at "nothing" doesn't do nothing; it lands on the very top of the file system instead of one specific folder deep inside it. So instead of deleting one folder's worth of Steam files, the app deleted everything on the computer that it had permission to touch. Some users lost every personal file they had, just from running an uninstall.

That absolute path — /home/fellow/projects/weather-app — means the same exact folder no matter what folder you happened to be sitting in when you typed it, because it's traced all the way from the root, /. A relative path like src/main.py only means something once you already know where "here" is. The Steam bug is what happens when code silently loses track of "here" and acts anyway.

3. The five commands that run everything

Everything above comes down to five commands. pwd prints your current absolute path — the honest answer to "where am I, exactly," the thing Steam's script never actually asked. ls lists what's in the current folder (or a folder you name). cd <folder> moves into a folder — a relative name moves relative to where you are, a path starting with / moves to that absolute location regardless of where you started. mkdir <name> creates a new folder inside the current one. touch <name> creates a new, empty file inside the current one.

Type these commands into the terminal above, one at a time, in this order:

  1. pwd — confirm where you're starting from
  2. ls — confirm the folder is empty
  3. mkdir weather-app — create the project folder
  4. cd weather-app — move into it
  5. mkdir src — create the src folder
  6. mkdir tests — create the tests folder
  7. touch README.md — create the README file
  8. cd src — move into src
  9. touch main.py — create the script file
  10. cd .. — move back up to weather-app
  11. pwd — confirm you landed back where you expect
Need a hint?

mkdir makes the folder, but you still have to cd into it afterward before anything you build next lands inside it instead of next to it.

6. Summary & reflection

A file system is a tree: one root, folders branching off it, files and more folders branching off those. pwd tells you exactly where you are in that tree right now. ls tells you what's actually around you before you act. cd moves you through it — relative to where you stand, or by absolute path regardless of where you stand. mkdir and touch build new branches and leaves. The Steam bug happened because one script skipped the first two and trusted a path it never confirmed.
