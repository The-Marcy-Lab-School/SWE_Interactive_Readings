The Missing Terminal

Every setup guide you'll follow this fellowship assumes one thing: a real Linux-style terminal, with real Unix commands, a real package manager, and tools like git and python3 that just work. On a Mac, that terminal is already there. On Windows, it isn't — and Microsoft's own engineers ran into that exact wall badly enough that they built an entire feature to fix it: the Windows Subsystem for Linux, or WSL. This reading is about what WSL actually is, and getting a real one running.

~13–14 minutes Interactive No setup needed to read

1. Why this exists

Back before WSL existed, a Windows developer who needed real Linux tools had exactly two bad options. Install a full virtual machine — VirtualBox or VMware, a whole second operating system running inside the first one, its own multi-gigabyte disk image, several GB of RAM permanently reserved just to keep it running in the background. Or dual-boot: partition the hard drive, install Ubuntu alongside Windows, and reboot the entire machine every time the task switched from "write code" to "reply to email." Neither is a small cost, and both were the honest answer for years.

Microsoft's own developers hit this wall constantly — enough that in 2016 Microsoft partnered with Canonical (the company behind Ubuntu) to ship something new: a real Linux environment that starts in about a second, shares files directly with Windows, and costs nothing to leave running. That's WSL. Not a simulation of Linux commands, and not a full second computer pretending to be one — a real Linux kernel, running alongside Windows on the same machine.

Where this is headed: once WSL is running, everything else this fellowship's environment setup asks you to do — installing git, running python3, navigating a real file system — works exactly the way it's written, no Windows-specific workaround needed. This is the one setup step that unlocks all the others.

3. Getting it installed

The entire install is one command, run from PowerShell or Windows Terminal opened as Administrator:

wsl --install

That single command downloads the WSL feature itself, installs a real Linux kernel, and sets Ubuntu as the default distro — all in one pass. After it finishes, Windows asks for a restart. On the first launch after restarting, Ubuntu asks you to create a username and password for that Linux environment specifically — separate from your Windows login, and worth writing down somewhere, since it's what you'll type every time a command needs elevated permission (sudo) from here on.

Referring to the steps above: put them in the order they actually happen.

  • Open PowerShell or Windows Terminal as Administrator
  • Run wsl --install
  • Restart the computer when prompted
  • Create a Linux username and password on first launch
Need a hint?

Nothing about Ubuntu can happen until the feature itself is installed, and nothing about the feature finishes installing until after the restart.

6. Summary & reflection

WSL exists because Microsoft's own developers needed real Linux tools without the cost of a full virtual machine or a dual boot — and now every Windows-based engineer in this fellowship gets that same real Linux environment for free, built into Windows itself. wsl --install, a restart, and a username/password are the entire setup.
