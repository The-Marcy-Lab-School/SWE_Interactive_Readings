The Fare That Went to the Wrong Ride

~13 minutes Interactive No setup needed to read

1. One set of variables, two rides, one bug

Here's roughly what Nimbus Rides' dispatch script looked like. A driver named Marcus picked up Amir first, then — before Amir's ride had finished and been billed — picked up Priya for a second ride along the way:

# Ride 1 begins
rider = "Amir"
fare = 22.50

# Ride 2 begins before Ride 1 has been billed
rider = "Priya"
fare = 14.00

# Ride 1 finally finishes and tries to bill its rider...
print("Charging", rider, "$" + str(fare))

That last line was supposed to bill Amir $22.50. Instead it printed Charging Priya $14.0 — because there was only ever one rider variable and one fare variable in the whole script. The moment Ride 2 started, it silently overwrote Ride 1's data, and Ride 1 had no memory of its own left to bill correctly. Amir was never charged. Priya's ride looked like it billed twice.

Renaming the variables (rider1, rider2, fare1, fare2...) would buy a little time, but it falls apart the moment Nimbus wants a third simultaneous ride, or a tenth. What Nimbus actually needs is a way to say: every ride gets its own separate, independent copy of this data — automatically, no matter how many rides exist at once. That's exactly what a Python class is for: a blueprint that produces as many independent objects as you need, each one holding its own values.

Both ride1 and ride2 came from the exact same class — the exact same blueprint — but the moment each one gets built, it gets its own separate set of values. That's the whole idea this reading is about.

3. Defining the class, line by line

Here's the full Ride class from the diagram above, on its own:

class Ride:
    def __init__(self, rider, fare):
        self.rider = rider
        self.fare = fare

Reading it line by line: class Ride: names the blueprint. def __init__(self, rider, fare): defines the setup method that runs the instant an object is built — self is always the first parameter of any method defined inside a class, and Python fills it in automatically with whichever object is currently being created; you never pass it yourself. rider and fare are ordinary parameters, just like in a regular function — they hold whatever values get passed in. The two lines underneath are where the actual saving happens: self.rider = rider takes the value that came in through the rider parameter and stores it as an attribute on this specific object, permanently, so it's still there later even after __init__ finishes running.

Building an object from this class — instantiating it — looks like calling a function:

ride1 = Ride("Amir", 22.50)
ride2 = Ride("Priya", 14.00)

Each of those two lines runs __init__ once, with self pointing at a brand-new, empty object each time. The first call sets that new object's rider to "Amir" and fare to 22.50, then hands it back as ride1. The second call does the same thing on a completely different new object, with completely different values, handed back as ride2. Nothing about building ride2 touches ride1 at all.

4. Two objects, two independent worlds

It's tempting to picture self.rider = rider as setting some single, shared box called rider that every Ride object peeks into. That's backwards. Every time __init__ runs, self points at a fresh, separate object, and self.rider = rider stores the value on that one object only. ride1 and ride2 don't share a rider attribute or a fare attribute at all — they each have their own copy, sitting in their own separate spot in memory, and one can change without the other ever noticing.

6. Summary & reflection

Nimbus Rides' bug happened because one set of plain variables was being asked to represent an unlimited number of rides at once. A class fixes that at the root: class Ride: defines the blueprint once, __init__(self, rider, fare) runs automatically every time a new Ride gets built, and self.rider = rider / self.fare = fare save that data onto that one object — never onto some single shared variable. ride1 = Ride("Amir", 22.50) and ride2 = Ride("Priya", 14.00) can now exist at the same time, indefinitely, each fully independent of the other.
