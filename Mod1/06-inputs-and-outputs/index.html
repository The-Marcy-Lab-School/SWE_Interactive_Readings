The Receipt That Said 33 Cookies

~14 minutes Interactive No setup needed to read

1. A receipt that said 33 cookies

A school runs a bake sale every Friday. Cookies come in 2-packs at $1.10 a pack, and the volunteer working the table rings up each order on a laptop with a short Python script called register.py. The first version had the number of packs typed straight into the file:

The first register.py
the order is typed into the code

PACK_PRICE = 1.10

def main():
    packs = 3
    print("Cookies:", packs * 2)
    print("Total: $", PACK_PRICE * packs)

main()

What it printed

Cookies: 6
Total: $ 3.3000000000000003

The count is right and the receipt is not. A receipt should read $3.30. print() put a space between the dollar sign and the number because a space is what it puts between values unless you tell it otherwise. It printed all 17 digits because 1.10 * 3 is not stored as exactly 3.3 inside a computer.

The packs = 3 line was the bigger problem. A program is hard-coded when you have to edit its code to get a different result. Every single order meant stopping, opening register.py, changing that number, and saving the file, while people waited in line.

So someone changed one line. packs = 3 became packs = input("How many 2-packs? "), and nothing else in the file changed. Here is the next order, where the volunteer typed 3:

How many 2-packs? 3
Cookies: 33
Traceback (most recent call last):
  File "register.py", line 6, in main
    print("Total: $", PACK_PRICE * packs)
TypeError: can't multiply sequence by non-int of type 'float'

Six cookies turned into 33, and then the register stopped working in front of a customer. input() hands back whatever was typed as a string, every time, so packs held the text "3" rather than the number 3. Multiplying a string by 2 repeats it, which is how "3" became "33". Multiplying a string by a decimal means nothing in Python, so the next line stopped the program.

Fixing that register takes three things: how Python stores and slices text, how print() and f-strings shape what goes out, and how input() and the conversion functions bring what a person typed back in as a number.

3. Strings, one character at a time

The bake sale keeps a sign-in sheet as well. A second script, signin.py, takes a volunteer's name and writes a short tag next to each shift:

signin.py

name = "Jordan"

print("Initial:", name[0])
print("Tag:", name[0:3].upper())
print("Letters:", len(name))
print("Last letter:", name[-1])

What it printed

Initial: J
Tag: JOR
Letters: 6
Last letter: n

A string is a sequence of characters between single or double quotes. Every character sits at a numbered position called an index, and the counting starts at 0. Bracket notation reads the character at an index, so name[0] is the first character. Python also counts backwards from the end: -1 is the last character and -2 is the one before it. len(name) counts the characters, spaces included.

Two numbers inside the brackets take a slice, which is a piece of the string. A slice runs from the start index up to but not including the end index, so name[0:3] gives three characters rather than four. The diagram below lays out both sets of index numbers for "Jordan", plus the slice and the one position that does not exist.

Later, signin.py was changed to ask for the name instead of holding one: name = input("Volunteer name: "). A volunteer in a hurry pressed Enter without typing anything, so name held "", a string with no characters in it.

Methods, and the in operator

A method is a function attached to a value, and you call it with dot notation: value.method(). String methods either answer a question about a string or build a new string from it. A string cannot be changed in place, so a method like upper() hands back a new string and leaves the original alone.

Four checks on one order note

order = "2 packs, no brownies"

print(order.upper())
print(order.startswith("2"))
print("brownie" in order)
print(order.find("packs"))

What it printed

2 PACKS, NO BROWNIES
True
True
2

in is an operator rather than a method, so it is written between the two strings: "brownie" in order asks whether the second string contains the first. find gives the index where a piece of text starts, which is 2 here because "packs" begins at the third character of order.

4. Shaping what comes out

print() takes any number of values, separated by commas, and puts them all on one line:

Four values, one print()

print("Cookies:", 6, "Total:", 3.3)

What it printed

Cookies: 6 Total: 3.3

Two keyword arguments control the spacing. sep is what goes between the values, and its default is a single space. end is what goes after the last value, and its default is "\n", the new line character. That default is the reason every print() starts on a fresh line.

Setting sep and end

print("a", "b", "c", sep="-")
print("loading", end="")
print("...", end="")
print("done")

What it printed

a-b-c
loading...done

That default space is what put a gap between the dollar sign and the number on the bake sale receipt. print("Total: $", PACK_PRICE * packs) hands print() two separate values, so print() separated them.

f-strings put the values inside the text

Write an f before the opening quote and any expression inside curly braces gets worked out and dropped into the string. That way the words and the values sit in the order they will be printed, and no commas decide the spacing for you:

The same receipt as an f-string

packs = 3
total = packs * 1.10

print(f"{packs} packs, ${total}")

What it printed

3 packs, $3.3000000000000003

The gap is gone and the 17 digits are still there. Computers store decimal numbers in a way that is very slightly inexact, so 1.10 * 3 comes out as 3.3000000000000003, and print() shows every digit it was given.

A format specifier says how a value should be displayed. Put a colon after the expression, then the format. .2f means "a decimal number with exactly two digits after the decimal point":

The same f-string with a format specifier

print(f"{packs} packs, ${total:.2f}")

What it printed

3 packs, $3.30

.2f changes only how the number is displayed. The value stored in total is untouched, so later arithmetic still uses the full number.

Here are two print() calls from a receipt line.

packs = 3
price = 1.10

print("Packs", packs, sep=": ", end=" | ")
print(f"Total: ${packs * price:.2f}")

What do those two calls print?

5. Bringing what a person types in

input(prompt) prints the prompt, waits for someone to type a line and press Enter, and hands back what was typed. The space at the end of the prompt text keeps the answer from running into the question.

name = input("Volunteer name: ")
print(f"Thanks, {name}!")

Whatever comes back is a string. Typing 3 gives you "3", not the number 3, and nothing converts it on your behalf. That one rule is the whole reason the bake sale register printed 33 cookies.

People also type messily. They add spaces at the ends, and they use capitals where you expected small letters. strip() removes the spaces from both ends of a string and lower() makes every letter small. Each one hands back a new string, so you can call the second on the result of the first:

Cleaning up a messy answer

answer = "  Y "

print(answer.strip().lower() == "y")
print(answer.lower() == "y")

What it printed

True
False

Calling one method on the result of another is called method chaining, and it works because strip() hands back a string, which has a lower() method of its own. The second comparison is False because lower() changes letters and leaves the spaces alone, so " y " is not equal to "y".

6. Turning what was typed into the right type

Arithmetic and comparisons only make sense between values of the right type, and everything out of input() is a string. Type conversion is the fix: int(), float(), str(), and bool() each turn a value into one of Python's types.

Three conversions

print(int("42") + 1)
print(float("0.50") * 2)
print(str(42) + "!")

What it printed

43
1.0
42!

Anything can be turned into a string, and int() is pickier. int("hello") raises a ValueError and stops the program, because "hello" is not a number written out in digits. A volunteer who types three instead of 3 would take the register down.

The isdigit() method is the guard against that. It hands back True when a string is made only of digits, so you can check first and print a message instead of crashing:

packs_typed = input("How many 2-packs? ").strip()

if not packs_typed.isdigit():
    print(f"'{packs_typed}' is not a whole number. Nothing was rung up.")
    return

packs = int(packs_typed)

isdigit() hands back False for "3.5" as well, because a decimal point is not a digit. For an amount typed with a decimal point you want float(), and isdigit() is the wrong check for it.

A Y or N answer, turned into a boolean

The register's last question has two acceptable answers, and the rest of the program needs a boolean rather than text. One comparison does the whole job:

wants_receipt = input("Print a receipt? (Y/N) ").strip().lower() == "y"

strip() drops stray spaces, lower() turns a typed Y into y, and == "y" produces True or False. From that line on, wants_receipt holds a boolean, so if wants_receipt: works the way any other condition does.

Check every answer a volunteer could type that sets wants_receipt to True. More than one is possible.

Need a hint?

Work each answer through the chain one step at a time: strip() first, then lower(), then compare what is left against the single character "y". Two of the six end up as strings longer than one character.

From hard-coded to asking

Here is the finished register.py. Nothing about it is hard-coded any more: the same file handles every order of the day, because it asks instead of being edited.

The finished register.py

PACK_PRICE = 1.10

def main():
    packs_typed = input("How many 2-packs? ").strip()

    if not packs_typed.isdigit():
        print(f"'{packs_typed}' is not a whole number. Nothing was rung up.")
        return

    packs = int(packs_typed)
    total = packs * PACK_PRICE
    wants_receipt = input("Print a receipt? (Y/N) ").strip().lower() == "y"

    print(f"Cookies: {packs * 2}")
    print(f"Total: ${total:.2f}")
    if wants_receipt:
        print("Receipt printed.")

main()

One order, typing 3 then Y

How many 2-packs? 3
Print a receipt? (Y/N) Y
Cookies: 6
Total: $3.30
Receipt printed.

Try it. Five lines from the finished main() are out of order. Click them in the one order that makes the register work. The guard is written on a single line here so that every step stays one line long.

  • total = packs * PACK_PRICE
  • packs = int(packs_typed)
  • packs_typed = input("How many 2-packs? ").strip()
  • print(f"Total: ${total:.2f}")
  • if not packs_typed.isdigit(): return
Need a hint?

A line can only use a variable that an earlier line created. Find which line creates packs_typed, which one creates packs, and which one creates total, and the order falls out. The guard has one more rule of its own: it has to run before the conversion it is protecting.

7. Summary and reflection

A string is a sequence of characters, each at a numbered position starting at 0, and a negative index counts back from the end. A slice stops just before its end index, and an index the string does not have raises an IndexError. print() puts sep between its values and end after them, and an f-string with :.2f displays a decimal with exactly two digits after the point. input() always hands back a string, so strip() and lower() clean it up and int() or float() turn it into a number, with isdigit() checking first.
