The Loop That Never Stopped

~13 minutes Interactive No setup needed to read

1. A trading system that could not stop repeating itself

Knight Capital was a Wall Street trading firm whose software decided, on its own, which stock orders to send to the market. In 2012 the firm pushed new trading code to eight servers, and one server missed the update. That server kept running an old, retired routine called Power Peg. Power Peg sent buy or sell orders for a stock over and over. It was supposed to stop as soon as a running count of shares filled reached the size of the order. That is the shape of a loop: repeat while something is true, stop the moment it stops being true. Years earlier, Knight had moved the counting code somewhere else and never re-tested Power Peg against that change. By 2012 the count Power Peg read never went up, so the thing that was supposed to end the repeating never happened.

On August 1, 2012, a new order flag woke Power Peg up on that one server. It fired off buy and sell orders for about 45 minutes, roughly 4 million trades across 154 stocks, and no line of code stopped it. A person finally shut the server down by hand. Knight lost $460 million and nearly went out of business. The mistake is one every Python beginner makes too: write a loop that repeats until something changes, and leave out the line that changes it. The next few sections cover the two kinds of loop Python gives you, when each one fits, and how to stop one on purpose.

Source: the U.S. Securities and Exchange Commission's 2013 administrative order against Knight Capital Americas LLC, Release No. 34-70694.

3. Writing a line 100 times, or writing it once

Knight's order router had to send the same kind of order again and again. Written out by hand, 100 orders means 100 near-identical lines, and the only thing that changes between them is a number. Here is that by-hand version next to the same job written as a for loop:

Written out by hand
one line per order, 100 of them

send_order(0)
send_order(1)
send_order(2)
send_order(3)
send_order(4)
# and 95 more lines like this

The same job as a for loop
two lines, any number of orders

for i in range(100):
    send_order(i)

range(100) produces the numbers 0, 1, 2, and so on up to 99. The variable i takes one of those numbers on each pass. Every pass of a for loop does the same three things:

  1. Take the next number out of the range and assign it to i.
  2. Run the indented block.
  3. Go back to the first step, until the range runs out.

The rule for range(n) is "n numbers, starting at zero." So range(5) produces five numbers and the first one is 0, which makes the last one 4. Counting from zero is the convention everywhere in Python. Here is range(5) printed one number per line:

The code

for i in range(5):
    print(i)

What it prints

0
1
2
3
4

Five lines, not six. range() also takes a starting point and a step size:

range(1, 101)      # 1, 2, 3, ... 100
range(0, 20, 5)    # 0, 5, 10, 15
range(10, 0, -1)   # 10, 9, 8, ... 1

Given a start and a stop, range() begins at the start and ends just before the stop. That is why range(1, 101) gets you the numbers 1 through 100.

You run this loop.

for n in range(1, 5):
    print(n)

What is the first number it prints, and what is the last?

Need a hint?

Two numbers inside range() means a start and a stop. The start is included. The stop is where range() ends, and it is not one of the numbers produced.

Strings are iterables too

A for loop can walk through the characters of a string with no range() involved at all:

The code

for letter in "GOOG":
    print(letter)

What it prints

G
O
O
G

Any value a for loop can walk through one element at a time is called an iterable. A range() is an iterable of numbers, and a string is an iterable of characters. Lists are iterables as well, so the same loop shape works on them.

4. Known count, or unknown count?

The number of repetitions is what decides which loop to write. If you can work the count out before the loop starts, write a for loop. If the count depends on something that happens while the program runs, write a while loop.

Shipping every order in a batch has a count you already have, so ship_batch uses a for loop:

def ship_batch(orders):
    for order_id in orders:
        ship(order_id)

Python walks orders once per item, in order, and stops on its own the moment the items run out. Nothing has to count, and nothing can forget to stop.

Draining a queue is different. drain_queue uses a while loop:

def drain_queue(queue_size):
    while queue_size > 0:
        process_next_order()
        queue_size -= 1

Before every pass, including the first one, Python tests queue_size > 0. The loop ends the first time that test comes out False. It only comes out False because queue_size -= 1 runs inside the body and brings queue_size down to 0. Delete that one line and queue_size stays at its starting value forever, so drain_queue keeps processing orders for as long as the computer stays on. That is the Knight Capital bug in four lines.

5. Stopping on purpose: while True, break, and continue

Sometimes there is no condition to write at the top of the loop, because the thing you are waiting for is the only reason to stop. A price watcher is one of those. It reads quotes as they arrive and buys the first time a quote comes in at 97 or less. Nobody can know in advance how many quotes that takes.

import random

def next_quote():
    return random.randint(95, 110)

while True:
    quote = next_quote()
    if quote <= 97:
        print(f"Bought at {quote}.")
        break
    if quote > 105:
        print(f"{quote} is outside the range we track. Ignoring it.")
        continue
    print(f"{quote} is above our price. Waiting for the next quote.")

print("Trading session over.")

random.randint(95, 110) picks a whole number from 95 to 110, so next_quote() stands in here for a price arriving from the market. Chapter 1.9 covers how import works. For now it is a price feed.

while True is a condition that is always true, so this loop has no natural ending and break is the only way out of it. break ends the loop immediately, and the program carries on with the first line after the loop body. continue ends the current pass only and sends Python straight back to the top of the loop, so the lines under it are skipped this time around. A quote above 105 therefore never reaches the "Waiting for the next quote." line.

How break is different from return

Both statements leave the loop, and that is where the similarity stops. break ends the loop. return ends the whole function the loop is sitting inside, so no line after the loop in that function ever runs. Here are two functions that are identical except for that one word:

watch_with_break
leaves the loop

def watch_with_break():
    while True:
        if next_quote() <= 97:
            print("Bought.")
            break
    print("Session over.")

It printed:

Bought.
Session over.

watch_with_return
leaves the whole function

def watch_with_return():
    while True:
        if next_quote() <= 97:
            print("Bought.")
            return
    print("Session over.")

It printed:

Bought.

The missing line is the whole difference. watch_with_return never prints "Session over." because return ended the function before Python got there.

When a loop has no way out

An infinite loop is a loop whose condition never becomes False. The program keeps running and keeps using the computer's resources until something outside the program stops it. while True is an infinite loop written on purpose, and the break is what makes it safe to write. Power Peg had the same shape with nothing that could ever fire the break, which is why a person had to shut the server off.

If you start one by accident, press Control+C in the Terminal. Python prints KeyboardInterrupt, which means you interrupted it. Nothing is wrong with your computer.

6. Keeping a running count

A loop that handles one order per pass can report on that one order and nothing more. To say how many of 100 orders came back filled, the program needs a number that survives from one pass to the next. That number is an ordinary variable created before the loop starts, and each pass adds to it. Here is fill_report, which does exactly that:

import random

def route_order():
    return random.choice(["filled", "rejected"])

def fill_report(orders):
    filled = 0
    for i in range(orders):
        if route_order() == "filled":
            filled += 1
    print(f"{filled} of {orders} orders filled.")

fill_report(100)

One run printed:

52 of 100 orders filled.

The position of filled = 0 is the whole trick, and the rule behind it is simple: an assignment statement runs every single time Python reaches it. Written before the for loop, filled = 0 is reached once, so the count starts at zero and then only ever grows. Move that same line into the loop body and Python reaches it on every pass, which sets the count back to zero every pass.

filled += 1 is shorthand for filled = filled + 1. It reads the current count, adds one, and stores the result back in the same variable. That is what carries the total forward across passes.

Here is count_filled, where the counter line sits inside the loop body instead.

def count_filled(orders):
    for i in range(orders):
        filled = 0
        filled += 1
    print(filled)

count_filled(5)

What does count_filled(5) print?

Need a hint?

Walk through a single pass. Python reaches filled = 0, then filled += 1. Now ask what filled equals at the start of the next pass, and whether any pass can leave it any higher.

7. A loop inside a loop

Reporting one line per stock takes one loop. Reporting one line per stock for each of three trading days takes that first loop again, once per day. Writing a loop inside another loop's body gives you that, and the pattern is called a nested loop:

for day in range(3):
    print(f"Day {day}:")
    for stock in range(5):
        print(f"  day {day}, stock {stock}")

The rule that governs a nested loop is that the inner loop completes all of its passes for every single pass of the outer loop, and it starts over from the beginning each time. So for stock in range(5) runs from 0 to 4, finishes, and then runs from 0 to 4 again on the next day.

8. Summary and reflection

Write a for loop when you can work out the number of repetitions before the loop starts, and let range(n) count for you from 0 up to n - 1. Write a while loop when the count depends on something that happens while the program runs, and make sure a line inside the body changes what the condition tests. break leaves the loop, return leaves the whole function. A running count lives in a variable created before the loop, because an assignment inside the body would reset it on every pass.
