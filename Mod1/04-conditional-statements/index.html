Zero Is Not Nothing

~13 minutes Interactive No setup needed to read

1. A week that looked like missing data

Ledger Lite is a simulated budgeting app that shows a student one line a week: how much money they spent. During its first week of testing, a student who spent nothing at all opened the app and read "We couldn't find your spending data." She emailed support to ask whether the app had lost her records. The app had not lost anything. It had her number, and her number was 0.

Here is the function that produced that message:

def weekly_summary(total):
    if not total:
        return "We couldn't find your spending data."
    return f"You spent ${total} this week."

Read if not total: out loud and it sounds like "if there is no total." Python reads that line differently, and the gap between those two readings is what this whole reading is about: which line of a program runs next, and what an if statement really does with the value you hand it.

3. Control flow, and why the order of the conditions matters

Python executes the statements of a program top to bottom. That order is called control flow. An if / elif / else chain changes it: Python tests each condition from the top, runs the first branch whose condition is True, and skips the rest of the chain entirely.

Ledger Lite uses a chain to label how a week went:

def spending_tier(total):
    if total > 200:
        return "Over budget"
    elif total > 100:
        return "Getting close"
    else:
        return "On track"

An elif only gets a turn when every condition above it tested False. That rule is the reason the order of the conditions is part of the logic, not a style choice. A developer who rearranges the chain to read "smallest first" writes this instead:

def spending_tier(total):
    if total > 100:
        return "Getting close"
    elif total > 200:
        return "Over budget"
    else:
        return "On track"

Now a student who spent $250 and a student who spent $120 read the exact same label. The student who spent $250 has already passed the over-budget line, and the app shows her nothing that says so, so she keeps spending. The diagram below traces spending_tier(250) through both versions.

The swapped version above is the one running. A student spends $340. What does spending_tier(340) return?

Need a hint?

Start at the top of the chain and test the conditions in the order they are written. Stop at the first one that is True, because Python stops there too.

4. Boolean context: what an if does to the value you give it

An if statement does not require a boolean. It creates a boolean context, which means Python first converts whatever value follows if into True or False by calling the bool() function on it.

bool() follows one rule, and it is worth learning as a rule rather than as a list of examples. All values are truthy except for None, False, the numbers 0 and 0.0, the empty string "", and empty collections such as [] and {}. Those are the falsy values. Everything else Python can hold is truthy.

print(bool(0))        # False
print(bool(""))       # False
print(bool(None))     # False
print(bool([]))       # False  (an empty list)
print(bool(100))      # True
print(bool("hello"))  # True

That rule explains the bug from the start of this reading. The student spent nothing, so weekly_summary received total = 0. The if not total: line placed 0 in a boolean context, bool(0) produced False, and not False produced True. The return on the next line ran and handed back "We couldn't find your spending data." The function never asked whether the data existed. It asked whether the number was zero, and to bool(), zero and missing look identical.

The fix is to ask the question the team meant to ask:

def weekly_summary(total):
    if total is None:
        return "We couldn't find your spending data."
    return f"You spent ${total} this week."

is None compares a value against None itself instead of converting it to a boolean. 0 is not None, so the first return is skipped, and the student who spent nothing now reads "You spent $0 this week." Reach for if value is None: whenever "missing" and "empty" need different answers, and keep if not value: for when they can share one.

The one that surprises everybody: if "False": runs its body. "False" is a string with five characters in it, and every non-empty string is truthy. What the characters spell has no effect on bool(). This matters any time you test something a person typed, because a person always types a string.

Select every value below that is falsy. A falsy value sends an if statement to its else.

Need a hint?

Two of the six are text with characters inside them. Apply the rule to the value itself, not to what the value looks like it means.

5. Guard clauses: handling the exceptions first

Ledger Lite's summary has three things to rule out before it can print a dollar amount. Nobody may be logged in, the week's total may never have been recorded, and the total may come back negative, which happens when a refund gets counted twice. Written as nested if statements, each case pushes the real work one level further to the right:

def weekly_summary(user, total):
    if user is not None:
        if total is not None:
            if total >= 0:
                return f"You spent ${total} this week."
            else:
                return "That total looks wrong. We're checking it."
        else:
            return "We couldn't find your spending data."
    else:
        return "Please log in to see your summary."

The line that does the actual job sits four levels in. To know when that line runs, a reader has to hold three separate conditions in mind at the same time, and each else sits far below the if it belongs to. A reader who loses track of one condition will believe the function returns a dollar amount in a case where it really returns an error message.

A guard clause is a single if statement that returns before any later return gets a chance to run. Each guard takes one exceptional case and leaves the function immediately. Every line below a guard can then assume that guard's case is already ruled out, which is what keeps the main path at one indentation level:

def weekly_summary(user, total):
    if user is None:
        return "Please log in to see your summary."
    if total is None:
        return "We couldn't find your spending data."
    if total < 0:
        return "That total looks wrong. We're checking it."
    return f"You spent ${total} this week."

The last return needs no if of its own. If the program reaches that line, all three guards tested False, which tells you user exists, total exists, and total is zero or more. Two things pin the order down. Comparing None to a number with > raises an error, so the guard that catches None has to run before any comparison does. And section 3's rule still applies to guards: the first if that is True returns, so a wider condition placed above a narrower one will swallow it.

6. Conditional expressions: choosing a value on one line

Ledger Lite's summary line has to say "1 purchase" or "3 purchases". Choosing that one word with a full if / else statement takes four lines:

if count == 1:
    word = "purchase"
else:
    word = "purchases"
print(f"{count} {word} this week.")

Both branches assign to the same variable, word. A reader still has to read all four lines to learn that the only thing changing between them is one string.

A conditional expression chooses between two values and fits on one line. The form is value_a if condition else value_b. Python evaluates the condition, and the whole expression becomes value_a when the condition is True and value_b when it is False:

word = "purchase" if count == 1 else "purchases"
print(f"{count} {word} this week.")

Use a conditional expression when both branches produce a value for the same destination, such as one variable or one return. Keep the full if / else statement when the branches run genuinely different code, because an expression can only hand back a value.

7. Summary and reflection

An if / elif / else chain runs the first branch whose condition is True and skips the rest, so the order you write the conditions in decides where a value lands. An if also converts that value with bool(), which is why 0 and "no data" look the same to if not total: and why is None exists.
