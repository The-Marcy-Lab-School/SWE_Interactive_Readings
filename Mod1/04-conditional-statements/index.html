Zero Is Not Nothing

~14 minutes Interactive No setup needed to read

1. A week that looked like missing data

Ledger Lite is a simulated budgeting app that shows a student one line a week: how much money they spent. During its first week of testing, a student who spent nothing at all opened the app and read "We couldn't find your spending data." She emailed support to ask whether the app had lost her records. The app had not lost anything. It had her number, and her number was 0.

Here is the function that produced that message:

def weekly_summary(total):
    if not total:
        return "We couldn't find your spending data."
    return f"You spent ${total} this week."

Read if not total: out loud and it sounds like "if there is no total." Python reads that line differently, and the gap between those two readings is what this whole reading is about: which line of a program runs next, and what an if statement really does with the value you hand it.

3. Control flow, and why the order of the conditions matters

A week of $250 and a week of $20 should not get the same sentence out of Ledger Lite, and a program that runs every one of its lines every time cannot tell them apart. Python does run statements top to bottom by default, and that order is called control flow. An if / elif / else chain changes it. Python tests each condition from the top, runs the first branch whose condition is True, and skips the rest of the chain.

Ledger Lite uses a chain to label how a week went:

def spending_tier(total):
    if total > 200:
        return "Over budget"
    elif total > 100:
        return "Getting close"
    else:
        return "On track"

An elif only gets a turn when every condition above it tested False. That rule is the reason the order of the conditions is part of the logic, not a style choice. A developer who rearranges the chain to read "smallest first" writes this instead:

def spending_tier(total):
    if total > 100:
        return "Getting close"
    elif total > 200:
        return "Over budget"
    else:
        return "On track"

Trace $250 through that version. Python tests total > 100 first, 250 is greater than 100, so that branch returns "Getting close" and the chain ends before elif total > 200: is ever evaluated. Trace $120 and the same first condition is True again, so it returns "Getting close" too. Both students read the exact same label. The student who spent $250 has already crossed the $200 line the app was built to warn her about, and the one sentence it gives her says she is getting close to that line, which she reads as "not over it yet." Need a hint?

Start at the top of the chain and test the conditions in the order they are written. Stop at the first one that is True, because Python stops there too.

When the elifs become separate if statements

A wrong order hands a student a single label for the wrong tier. A second mistake hands her several labels at once, and it looks even more innocent on the page. Picture a developer tidying up spending_tier who deletes the el from each elif and changes nothing else. Every line still reads like a sensible condition. Here is that version, printing instead of returning so every line that runs is visible:

def label_week(total):
    if total > 100:
        print("Getting close")
    if total > 200:
        print("Over budget")
    if total > 500:
        print("Way over")
    if total <= 100:
        print("On track")

label_week(250)

An elif is attached to the if above it, and Python evaluates it only when that if tested False. A separate if is attached to nothing above it. Python evaluates every separate if, top to bottom, and runs the body of each one that is True. A chain therefore runs at most one branch, and a stack of separate if statements can run several in a single call.

Check every line that label_week(250) prints. More than one is possible.

Need a hint?

There is no elif here, so nothing above a given if can stop Python from evaluating it. Test all four conditions against 250 separately and check off every one that comes out True.

4. Boolean context: what an if does to the value you give it

An if statement does not require a boolean. It creates a boolean context, which means Python first converts whatever value follows if into True or False by calling the bool() function on it.

bool() follows one rule, and it is worth learning as a rule rather than as a list of examples. All values are truthy except for None, False, the numbers 0 and 0.0, the empty string "", and empty collections such as [] and {}. Those are the falsy values. Everything else Python can hold is truthy.

print(bool(0))        # False
print(bool(""))       # False
print(bool(None))     # False
print(bool([]))       # False  (an empty list)
print(bool(100))      # True
print(bool("hello"))  # True

That rule explains the bug from the start of this reading. The student spent nothing all week, so weekly_summary received total = 0. The if not total: line put 0 in a boolean context, and bool(0) produced False. The not operator flips a boolean to its opposite, so not False produced True and the return on the next line ran. weekly_summary never asked whether the data existed. It asked whether the number was zero, and bool() gives zero and missing the same answer.

Every falsy value is a "nothing" of some kind: no value, no quantity, no characters, no items. Name the no-value one, the no-quantity whole number, and the string with no characters between its quote marks.

Predict before you read on. This snippet catches almost everybody the first time:

if "False":
    print("printed")
else:
    print("skipped")

What does that snippet print?

That bug and this snippet share a shape: if not total: was the wrong question for Ledger Lite, and it is the right question most of the time. Any function handed something a person may have left empty has to decide first whether there is anything to work with at all:

def greet(name):
    if not name:
        return "I can't say hi if I don't know your name!"
    return f"Hi, {name}! Nice to meet you."

print(greet(""))      # I can't say hi if I don't know your name!
print(greet("Jane"))  # Hi, Jane! Nice to meet you.

The empty string is falsy, so bool("") is False and not "" is True, and the first return runs. "Jane" is a non-empty string and so it is truthy, which means not "Jane" evaluates to False, and Python skips past the guard to the greeting. You will meet the shape if not something: in nearly every program that takes input.

The one thing if not value: cannot do is tell None apart from 0 or "", since bool() answers False for all three. Ledger Lite needed exactly that difference. When the question really is "is this None?", write if value is None:, which compares the value against None itself instead of converting it to a boolean:

def weekly_summary(total):
    if total is None:
        return "We couldn't find your spending data."
    return f"You spent ${total} this week."

0 is not None, so the first return is skipped and the student who spent nothing reads "You spent $0 this week."

5. Guard clauses: handling the exceptions first

Ledger Lite's summary has three things to rule out before it can print a dollar amount. Nobody may be logged in, the week's total may never have been recorded, and the total may come back negative, which happens when a refund gets counted twice. Written as nested if statements, each case pushes the real work one level further to the right:

def weekly_summary(user, total):
    if user is not None:
        if total is not None:
            if total >= 0:
                return f"You spent ${total} this week."
            else:
                return "That total looks wrong. We're checking it."
        else:
            return "We couldn't find your spending data."
    else:
        return "Please log in to see your summary."

The line that does the actual job sits four levels in. To know when that line runs, a reader has to hold three separate conditions in mind at the same time, and each else sits far below the if it belongs to. A reader who loses track of one condition will believe the function returns a dollar amount in a case where it really returns an error message.

A guard clause is a single if statement that returns early. A return ends the function the moment it runs, so once a guard returns, not one line below it is evaluated. Each guard takes one exceptional case and leaves, which lets every line below it assume that case is already ruled out. That is what keeps the main path at one indentation level:

def weekly_summary(user, total):
    if user is None:
        return "Please log in to see your summary."
    if total is None:
        return "We couldn't find your spending data."
    if total < 0:
        return "That total looks wrong. We're checking it."
    return f"You spent ${total} this week."

Order matters for guards for the same reason it matters in an elif chain: the first guard whose condition is True returns, and the guards below it never run. Write the narrowest condition first.

The last return needs no if of its own. If the program reaches that line, all three guards tested False, which tells you user exists, total exists, and total is zero or more. Those are exactly the conditions the normal case requires, so there is nothing left for a condition on that line to test. The diagram below shows what the guards do to the shape of the function.

Two things pin the order down. Comparing None to a number with > raises an error, so the guard that catches None has to run before any comparison does. And the narrowest-first rule above still applies: the first guard that is True returns, so a wider condition placed over a narrower one will swallow it.

6. Conditional expressions: choosing a value on one line

Ledger Lite's summary line has to say "1 purchase" or "3 purchases". Both branches of a full if / else statement assign to the same variable, word, so a reader has to get through four lines to learn that the only thing changing is one string:

# Okay - an if statement picks which block of code runs
if count == 1:
    word = "purchase"
else:
    word = "purchases"

# Better - a conditional expression picks which value gets assigned
word = "purchase" if count == 1 else "purchases"

The form is value_a if condition else value_b, and the whole expression becomes value_a when the condition is True and value_b when it is False. A conditional expression can only hand back a value, so reach for one when both branches feed the same destination and keep the full if / else statement when they run different code.

7. Summary and reflection

An if / elif / else chain runs the first branch whose condition is True and skips the rest, so the order you write the conditions in decides where a value lands. Turn those elif statements into separate if statements and Python evaluates every one of them, so several branches can run on a single call. An if also converts the value you hand it with bool(), which is why 0 and "no data" look identical to if not total:.
