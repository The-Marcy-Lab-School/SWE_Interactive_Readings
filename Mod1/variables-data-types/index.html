The Gene That Became a Date

In 2016, researchers discovered that roughly one in five published genetics papers with a supplementary gene list contained an error, because Microsoft Excel had quietly turned real gene names, like SEPT2, into calendar dates. Nobody typed a date. A spreadsheet just decided, on its own, what type a piece of text "really" was. Every value in a running program has a type the same way, and this reading is about the four types Python uses constantly — int, float, str, bool — and how to keep control of them yourself instead of letting something else guess.

1. When a spreadsheet decided a gene was a date

Human genes have short official symbols — SEPT2, MARCH1, DEC1 — so scientists can refer to them quickly across papers and databases. In 2016, a team of Australian researchers (Ziemann, Eren, and El-Osta, published in Genome Biology) went looking through years of published genetics papers and found that about 20% of the ones with a supplementary gene list had at least one gene name silently mangled. SEPT2 had become the date "2-Sep." MARCH1 had become "1-Mar." The scientists hadn't typed a date anywhere. Microsoft Excel had opened their gene list, glanced at text that looked date-shaped, and rewritten it as a date automatically, before anyone saved the file.

The damage wasn't cosmetic. Once a gene symbol becomes a date, it's a different value entirely — sorting, searching, and matching it against any other dataset all silently point at the wrong thing, and nothing throws an error to say so. The fix scientists reached for wasn't a smarter spreadsheet setting: in 2020 the official body that assigns human gene symbols, the HUGO Gene Nomenclature Committee, permanently renamed the worst-offending genes so software could no longer mistake them for dates — MARCH1 became MARCHF1, SEPT1 became SEPTIN1, and so on. A 2021 follow-up study found the problem was still showing up in roughly 30% of newer papers.

Excel didn't do this out of carelessness. It did it because every single value has to be treated as some type, and when nothing pins that type down explicitly, the program decides for you — and it doesn't always decide the way you meant. That is exactly the problem this reading is about solving on purpose, in Python, before it ever gets the chance to guess.

3. A variable is a name, not a box

It's tempting to picture x = 5 as "a box called x with a 5 inside it." That mental model breaks the moment you write x = "hello" right after — did the 5 turn into text? It didn't. Python never changes a value in place like that. What actually happened both times is simpler: the name x got pointed at a value somewhere in memory. The first line points it at the integer 5. The second line points that same name at a completely different value, the string "hello", and the 5 is left with nothing pointing at it at all. A variable is a name attached to a value, not a container that becomes the value.

This matters because two values can look identical on the page and behave nothing alike, depending only on their type. count = 5 and code = "5" print the same single character. But count points at an integer, and code points at a string — and the exact same + operator does something different to each one:

On numbers, + means addition. On strings, + means concatenation — glue the two pieces of text together, end to end. Same symbol, two entirely different behaviors, and Python decides which one to run by checking the type of the values on either side of it, not by anything the symbol itself says. This is exactly the same category of problem as the gene-name story above: a value that looks like a number isn't automatically treated like one. A real-world example of the same trap: a US ZIP code like "02134" has to be stored as a str, because as an int it would quietly lose its leading zero and become 2134 — a different, wrong ZIP code, with no error to flag it.

* on a string repeats the text that many times, the same way + on two strings glues them together — neither one does math, because price here is a str, not a number. And Python's boolean values print exactly as True or False, capitalized, with no quotes.

5. Summary & reflection

A variable is a name pointing at a value, and assignment (=) is what points it there. Every value has a type — int, float, str, or bool among the basics — and that type decides what an operation like + actually does, not the symbol alone. Leaving a value's type to a guess is exactly what turned real gene names into calendar dates in thousands of spreadsheets; naming and typing a value on purpose is how a program avoids the same fate.
