The Gene That Became a Date

~10 minutes Interactive No setup needed to read

1. When a spreadsheet decided a gene was a date

Human genes have short official symbols — SEPT2, MARCH1, DEC1. In 2016, researchers found that about 20% of published genetics papers with a gene list had at least one name changed by accident. SEPT2 had become the date "2-Sep." MARCH1 had become "1-Mar." No one had typed a date — Microsoft Excel saw text that looked date-shaped and rewrote it automatically, before anyone saved the file. Once a symbol becomes a date, it's a different value entirely, and sorting or matching it against other data silently breaks with no error to warn anyone.

The real fix wasn't a smarter spreadsheet setting. In 2020, the group that officially names human genes renamed the ones most often mistaken for dates, so software could no longer confuse them — MARCH1 became MARCHF1, for example. Even so, a 2021 study found the problem still showing up in about 30% of newer papers. Excel wasn't being careless: every value has to be treated as some type, and when nothing states that type explicitly, the program guesses for you. That's exactly the problem this reading solves on purpose, in Python, before it ever gets the chance to guess.

3. A variable is a name, not a box

It's tempting to picture x = 5 as a box holding a 5. That breaks when you write x = "hello" right after — did the 5 turn into text? No. Python never changes a value in place. What really happens: the name x points at a value in memory, first the integer 5, then a different value, the string "hello" — nothing points at the 5 anymore. A variable is a name attached to a value, not a box that becomes it.

This matters because two values can look identical yet behave nothing alike, depending only on their type. count = 5 and code = "5" print the same character, but count points at an integer and code points at a string — so the same + operator does something different to each:

On numbers, + means addition. On strings, it means concatenation — gluing two pieces of text together. Same symbol, different behavior, decided by type. It's the same trap as the gene-name story: a US ZIP code like "02134" has to be stored as a str, since as an int it would lose its leading zero and quietly become 2134 — a different, wrong ZIP code, with no error to flag it.

Predict the output: type what each snippet prints, then check all four together.

x = 5 y = 5 print(x + y)
x = "5" y = "5" print(x + y)
price = "19.99" print(price * 2)
is_ready = True print(is_ready)
Need a hint?

* on a string repeats the text that many times, the same way + on two strings glues them together — neither one does math, because price here is a str, not a number. And Python's boolean values print exactly as True or False, capitalized, with no quotes.

Quotation marks are the tell: if a value has quotes around it, it's a str no matter what the text inside looks like — that's exactly how a gene name like SEPT2 is supposed to stay text instead of becoming a date.

5. Summary & reflection

A variable is a name pointing at a value, and assignment (=) is what points it there. Every value has a type — int, float, str, or bool among the basics — and that type decides what an operation like + actually does, not the symbol alone. Leaving a value's type to a guess is exactly what turned real gene names into calendar dates in thousands of spreadsheets; naming and typing a value on purpose is how a program avoids the same fate.
