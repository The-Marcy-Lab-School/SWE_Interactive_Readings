The Loop That Never Stopped

~14 minutes Interactive No setup needed to read

1. A trading system that couldn't stop repeating itself

On July 27, 2012, Knight Capital rolled out new trading software to eight servers that handled its automated order routing. Copying the new code onto all eight machines was supposed to be routine. One technician missed a server. That eighth machine kept running an old, retired piece of logic called "Power Peg" — code Knight had stopped using years earlier and assumed was gone for good.

On August 1, new orders from Knight's Retail Liquidity Program carried a flag value that, on the seven correctly-updated servers, meant "handle this the new way." On the eighth server, that same flag value woke Power Peg back up. Power Peg's whole job, back when it was actively used, was to keep sending buy or sell orders for a stock until a running count of shares already filled told it to stop. In 2005, Knight had moved that counting logic to an earlier point in the code and never re-tested Power Peg against the change. By 2012, on that one server, the count Power Peg checked no longer reflected how many shares had actually gone through — so the condition that was supposed to eventually say "stop, you're done" never said it.

For forty-five minutes, that server kept sending new orders for 212 incoming customer trades without regard to what had already executed — about 4 million trades in total, repeatedly buying high and selling low in over a hundred stocks. Nothing in the code itself was ever going to stop it; a person had to notice and shut the server down by hand. Knight lost $460 million and very nearly collapsed as a company. The SEC (the U.S. Securities and Exchange Commission, the federal agency that regulates stock trading) later fined it $12 million for the failure.

Source: the U.S. Securities and Exchange Commission's 2013 administrative order against Knight Capital, retold in detail in Doug Seven, "Knightmare: A DevOps Cautionary Tale," 2014.

Strip away the trading-floor specifics and the shape of the bug is exactly the shape of a mistake every Python beginner runs into at some point: a loop that's supposed to run until a condition becomes false, with no working way for that condition to ever actually become false. Knight's version involved a badly-retested, decade-old counting function. The beginner's version is almost always simpler: a single line, forgotten inside the loop body, that was supposed to update the one variable the loop's own condition depends on. That's what the rest of this reading is about.

3. for loops vs. while loops

Use a for loop when you already know the full set of things you're repeating over — a list of order IDs, a range of page numbers, every character in a string:

orders = ["A-101", "A-102", "A-103"] for order_id in orders: ship(order_id)

Python walks the list orders once per item, in order, and stops automatically the moment the list runs out. There's no manual counting, and no way to accidentally skip the stop — running out of items to walk through is the stop.

Use a while loop when you don't know in advance how many times you'll repeat, only the condition that should eventually end it:

queue_size = 3 while queue_size > 0: process_next_order() queue_size -= 1

Before every single pass, including the first one, Python re-checks queue_size > 0. The loop only ends once that check comes back False — and that only happens if something inside the loop body actually changes queue_size. Picture the same code with that one line, queue_size -= 1, deleted. Nothing else in the loop would change. Keep that picture in mind for the diagram and the step-through below.

6. Summary & reflection

A for loop is for something you can count out in advance: a list, a range, a string's characters. A while loop is for something that depends on a condition changing while the program runs, and it only stops if the code inside its body actually changes that condition. Forgetting that one update is a small, easy mistake, and it happens to beginners and to Wall Street trading systems alike.
