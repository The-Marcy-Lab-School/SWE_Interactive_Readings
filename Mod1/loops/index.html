The Loop That Never Stopped

1. A trading system that couldn't stop repeating itself

Knight Capital was a Wall Street trading firm that used automated software to route stock orders. In 2012, it rolled out new trading code to eight servers, but one server missed the update. That server kept running old, retired logic called "Power Peg," which was supposed to keep sending buy or sell orders for a stock only until a running count of shares already filled told it to stop — the classic shape of a loop that runs while a condition is true and stops the moment it turns false. Years earlier, Knight had moved that counting logic to a different point in the code and never re-tested Power Peg against the change. By 2012, the count Power Peg checked no longer matched reality, so the condition that was supposed to eventually turn false never did.

On August 1, 2012, a new order flag accidentally woke Power Peg back up on that one server. For forty-five minutes it kept firing off buy and sell orders, about 4 million trades across more than a hundred stocks, and nothing in the code could stop it. A person finally had to shut the server down by hand, after Knight had already lost $460 million and very nearly collapsed as a company. Strip away the trading-floor details, and it's the exact same mistake every Python beginner eventually makes: a loop meant to run until a condition goes false, with no working way for that condition to ever actually become false. That's what the rest of this reading is about.

Source: the U.S. Securities and Exchange Commission's 2013 administrative order against Knight Capital, retold in detail in Doug Seven, "Knightmare: A DevOps Cautionary Tale," 2014.

3. for loops vs. while loops

Use a for loop when you already know the full set of things you're repeating over — a list of order IDs, a range of page numbers, every character in a string:

orders = ["A-101", "A-102", "A-103"] for order_id in orders: ship(order_id)

Python walks the list orders once per item, in order, and stops automatically the moment the list runs out. There's no manual counting, and no way to accidentally skip that stop.

Use a while loop when you don't know in advance how many times you'll repeat, only the condition that should eventually end it:

queue_size = 3 while queue_size > 0: process_next_order() queue_size -= 1

Before every single pass, including the first one, Python re-checks queue_size > 0. The loop only ends once that check comes back False — and that only happens if something inside the loop body actually changes queue_size. Picture the same code with that one line, queue_size -= 1, deleted. Nothing else in the loop would change. Keep that picture in mind for the diagram and the step-through below.

6. Summary & reflection

A for loop is for something you can count out in advance: a list, a range, a string's characters. A while loop is for something that depends on a condition changing while the program runs, and it only stops if the code inside its body actually changes that condition. Forgetting that one update is a small, easy mistake, and it happens to beginners and to Wall Street trading systems alike.
