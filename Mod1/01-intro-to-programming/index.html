What Is a Program, Really?

~13 minutes Interactive No setup needed to read

1. The book that cost more than a house

In 2011 an out-of-print biology book called The Making of a Fly was listed on Amazon for $23,698,655.93. Nobody typed that price in. Two used-book sellers, profnath and bordeebook, each ran a small pricing script once a day. profnath set its price to 0.99 times bordeebook's price, always a little cheaper. bordeebook set its price to 1.27 times profnath's price, always a little pricier. Each script ran its lines in the order they were written and did exactly what each line said. Day after day the two prices pushed each other up, until a used paperback cost more than a house.

Neither script was broken. A program is a text file of lines, and a computer runs those lines in the order they appear, from the top of the file to the bottom. "Stop if this number gets ridiculous" is a line a person has to write, and a computer never adds it on its own. This reading takes apart a pricing script of the same shape: the kinds of line it is made of, the command that runs it, and the one function that lets you read a value before a customer does.

Source: biologist Michael Eisen spotted the listing and published the full price log.

3. A program is made of three kinds of line

Every line in a Python file is a comment, an expression, or a statement.

Comments start with #. The Python interpreter skips them completely, so a comment can say anything you want and the program behaves the same way. Comments exist for the next person to read the file, including you in six months.

Expressions are any piece of code that evaluates to a single value. 5 + 5 evaluates to 10. len("hi") evaluates to 2. A plain value like "hello" is an expression too, because it evaluates to itself. An expression on its own does nothing useful; it becomes useful once a statement does something with the value.

Statements are instructions that change the program. Storing a value under a name adds that value to the program's state, which is the data the program is holding at that moment. An if statement changes which line runs next.

Here is repricer.py, a script shaped like profnath's:

# repricer.py: match the competitor, a penny under
competitor_price = 20.00
our_price = competitor_price * 0.99

The first line is a comment, so the interpreter ignores it. The second and third lines are statements: each one stores a value under a name and changes the program's state. competitor_price * 0.99 on the third line is an expression. It evaluates to the single value 19.8, and then the statement stores that value under the name our_price.

Try it. Drag each line into the kind of line it is.

Ask one question per line. Does it start with #? Then it is a comment. Does it work out to a single value and stop there? Then it is an expression. Does it store something or decide which line runs next? Then it is a statement.

4. Running the file with the Python interpreter

A .py file on its own is just text. The Python interpreter is the program that reads a .py file and executes it, one statement at a time, top to bottom. You start the interpreter from the Terminal by typing python3 and the name of the file you want it to read:

python3 repricer.py

Run repricer.py that way and the Terminal gives you nothing back. That is the right result, and it catches almost everybody the first time. The interpreter read all three lines and stored both values. A program shows you a value only when a line of the program asks it to, and repricer.py has no such line.

The simulator here has three files in it. repricer.py stores two values and says nothing. repricer_v2.py does the same work and then displays the price. counter.py adds 1 to a number one hundred million times and also says nothing, which takes real seconds of real work. Run these five commands, in order:

  1. ls — see which files are in this folder
  2. cat repricer.py — read a file without running it
  3. python3 repricer.py — run it, and notice what comes back; the simulator writes (no output) where a real Terminal just returns you to the prompt
  4. python3 repricer_v2.py — run the version that displays its price
  5. time python3 counter.py — ask the Terminal to time a file that displays nothing

counter.py takes about four seconds to finish and displays nothing at all. What does that tell you?

5. Reading a value with print()

print() is a built-in function that displays text in the Terminal. Its main job is letting you read a value the program worked out, so you can tell whether the program worked it out correctly. profnath's price climbed for weeks because no person read the new number each day; a print() line puts that number where a person can read it.

Add one line to repricer.py and the price appears:

# repricer.py: match the competitor, a penny under
competitor_price = 20.00
our_price = competitor_price * 0.99
print(our_price)

Output:

19.8

19.8 on its own tells you the number but not what the number is. Most of the time you want words around it. Put an f in front of the opening quote and Python evaluates any expression you write inside curly braces, then places its value into the text. A string written that way is an f-string.

The two versions differ by one character, the f, and they display different things:

With the f
Python fills in the value

print(f"Our new price is ${our_price}")

Output:

Our new price is $19.8

Without the f
the braces are ordinary characters

print("Our new price is ${our_price}")

Output:

Our new price is ${our_price}

The $ is just a character in the text either way. The f is what tells Python to treat {our_price} as an expression to evaluate rather than as four characters to display.

Try it. This script has to display Price: $19.8. Type the missing argument to print().

Wanted output:

Need a hint?

Start with f, then an opening quote. Write the words you want exactly as they should appear, and put our_price inside curly braces at the spot where the number belongs.

6. Control flow: which line runs next

Control flow is the order in which lines of code are executed. A computer runs one statement at a time, and the default order is the order you wrote them in: the top of the file first, the bottom of the file last.

print("1")
print("2")
print("3")

Output:

1
2
3

Two kinds of statement change that order. An if statement can cause lines to be skipped. A loop can cause the same lines to run more than once. Nothing else in a Python file moves the interpreter off the straight path down the page.

Here is the sanity rule profnath's script never had, written as an if statement in a file named check_price.py:

our_price = 19.80

if our_price > 1000:
    print("Check this price.")
print("Done.")

Output:

Done.

19.80 > 1000 is False, so the interpreter skips the indented print("Check this price.") line entirely and carries on with print("Done."). Give our_price a value of 23698655.93 instead and that same if statement runs the line it skipped before, and somebody finds out. The diagram compares the two paths.

A loop changes the order the other way. counter.py from the simulator is four lines long, and the line that does the adding is written once:

# counter.py: count to 100 million and say nothing about it
x = 0
for i in range(100_000_000):
    x += 1

The interpreter runs x += 1 one hundred million times before it reaches the end of the file. That is why time python3 counter.py reports seconds of work for a file that displays nothing.

Check every line that changes the order Python runs statements in. More than one is possible.

Need a hint?

Two of the four change the program in some way without touching the order. One changes nothing at all, because the interpreter never reads it as code. Ask of each line: could the interpreter end up skipping a line, or running a line twice, because of it?

7. Code style

Code style is the formatting of code in a way that makes it easier to read and understand. Python's conventions are written down in a document called PEP 8: four spaces per level of indentation, spaces around operators such as <=, and lowercase names joined by underscores, like our_price.

Indentation is the one part of that list the interpreter cares about. Whenever a line ends with a colon, the lines that belong to it have to be indented underneath it, which is how the interpreter knows that print("Check this price.") belongs to the if in check_price.py and print("Done.") does not. Get the indentation wrong and the interpreter raises an IndentationError and refuses the whole file before running a single line.

8. Summary and reflection

A program is a text file of comments, expressions, and statements. The Python interpreter reads that file when you type python3 and the file name, and it executes the statements one at a time, from the top of the file to the bottom. That order is called control flow, and only two kinds of statement change it: an if statement can skip lines, and a loop can repeat them. A program displays a value only where a print() line asks it to, which is why a script can run for weeks, do a great deal of work, and show nobody what it is doing.
