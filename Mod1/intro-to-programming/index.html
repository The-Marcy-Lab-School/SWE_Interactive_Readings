What Is a Program, Really?

~11 minutes Interactive No coding experience needed

1. The book that cost more than a house

The two sellers were called profnath and bordeebook, and neither of them was doing anything sneaky. Profnath's program checked bordeebook's current price once a day and set its own price to 0.9983 times that number, always coming in just slightly cheaper. Bordeebook's program did the mirror-image thing: it checked profnath's price and set its own to 1.270589 times that number, always coming in noticeably more expensive, as if to say "the cheaper copy is basically sold out, so mine is the premium option." Each program was simple, each program worked exactly as written, and each program ran once more the next day using whatever number the other program had just produced.

That is a loop with no exit condition. Profnath's higher output became bordeebook's input, and bordeebook's higher output became profnath's input the next day, over and over, each one multiplying a slightly bigger number. On April 18th the price hit its peak: $23,698,655.93. The following day, a human being finally noticed and manually reset profnath's price to a sane $106.23 — at which point bordeebook's program, still just following its one instruction, promptly and obediently set its own price to $106.23 times 1.270589, or $134.97. (The full price log survives; a biologist named Michael Eisen first spotted the listing and wrote up exactly what he found.)

Neither program had a bug in it, in the sense of doing something other than what its code said. Both programs did precisely what they were told, every single day. The actual problem is what was never told to them: nobody wrote an instruction for "and stop if this number gets ridiculous," because no human engineer imagined they needed to spell that out. A person would never let a used book's price wander past a million dollars without stopping to ask "wait, does this look right?" A computer does not do that unless a line of code specifically tells it to. It has no instinct for "ridiculous." It has no fallback plan. It has the instructions it was given, and it runs them.

That single idea, that a computer will keep doing exactly what its instructions say with zero built-in judgment about whether the result makes sense, is the foundation everything else in programming sits on top of. Before any Python syntax, this is the mental model worth having solid.

3. Instructions run in order, exactly as written

Two things are true of every program, from a five-line pricing bot to a full application: the instructions run one after another, in the exact order they're written, and each one runs exactly as written, with no step where the computer pauses to guess at your intent. Change the order of two steps and you often get a different, sometimes broken, result, even though every individual instruction is still perfectly correct on its own. Leave a step vague, or skip one the computer would need, and there's no built-in judgment to quietly patch the gap. A person filling in a vague recipe uses common sense without noticing they're doing it. A computer has no such fallback to fall back on.

The classic way to see this is with a task everyone already knows how to do: making a peanut butter sandwich. Compare a vague version of the instructions against an exact one.

Notice that "put peanut butter on" isn't actually an instruction a literal executor can run at all: on what, with what, how much? A human reader quietly fills in "on the bread, with a knife, a reasonable amount" without even noticing there was a gap. A computer has nothing to fill it with unless a person wrote that detail down first. This is exactly the same gap that let profnath and bordeebook's prices run to $23 million: "multiply by this number" is a perfectly exact instruction on its own, but "and stop if the result looks ridiculous" was never written down anywhere, so it was never part of what either program actually did.

Try it: here's a different everyday task, broken into steps but shuffled out of order. Put them back in the order a person (or a program) actually has to perform them.

  • Fill the kettle with cold water
  • Turn on the kettle and wait for the water to boil
  • Put a tea bag in the mug
  • Pour the boiling water into the mug
  • Wait 3-4 minutes, then take the tea bag out
Need a hint?

Nothing can boil before there's water in the kettle, and nothing can be poured before it's finished boiling. The tea bag can go in the mug any time before the pour, but it can't do anything on its own after that except sit and steep.

6. Summary & reflection

Two sellers' pricing programs multiplied a number back and forth until a used book hit $23.7 million, not because either program had a bug, but because "stop if this gets ridiculous" was never written down as an instruction. Every program, from that pricing bot to the first line of Python this fellowship writes, works the same way: instructions run in the exact order they're written, each one exactly as written, with no common-sense fallback for anything left vague or missing.
