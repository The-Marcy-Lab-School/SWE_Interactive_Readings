Off By One Song

~11 minutes Interactive No setup needed to read

1. The bug: "skip to 3" landed on song 4

QueueUp is a small app a coffee shop uses to run its lounge playlist: customers pick songs, and the app plays them in order. Here's the actual queue sitting behind QueueUp's bug report, exactly as it would look in Python:

queue = ["Skyline Drive", "Paper Boats", "Neon Static", "Better Days", "Midnight Coast"]

Square brackets create a list: an ordered, changeable collection, written as comma-separated values between [ and ]. Order matters here in a way it doesn't for every Python collection — this list remembers that "Skyline Drive" comes before "Paper Boats," and Python gives every item a numbered position, called an index, based on exactly where it sits.

Here's where QueueUp's bug came from. Whoever wrote the "skip to song" feature reached for the everyday way people count (first, second, third) and wrote queue[3] to mean "the 3rd song." But Python doesn't start counting at 1; it starts at 0. So queue[0] is the first song, queue[1] is the second, and queue[2] is the third. That makes queue[3] actually the fourth song, "Better Days." Every single listener who asked for song 3 got song 4 instead, and nobody on the team noticed until a regular in the lounge asked out loud why the app kept skipping ahead.

Every box in that row has two valid addresses. Counting from the front, "Neon Static" is queue[2]. Counting from the back, that exact same song is queue[-3]. Negative indexes always count from the end of the list, and queue[-1] is a fast, reliable way to grab the last item without needing to know how long the list is.

4. Adding a song: .append()

Nothing about a list is fixed once it's created. To add a new song to the end of the queue, Python lists have a built-in method, .append(), that adds exactly one new element after everything already there:

queue.append("Ocean Drive")

After that line runs, queue has six songs in it, and "Ocean Drive" sits at index 5 — one past where the last song used to be, because .append() always adds to the end, never the front or the middle.

6. Summary & reflection

A Python list holds items in order, and every item has an index — its position counted from the front, starting at 0, or from the back, starting at -1. QueueUp's bug happened because "the 3rd song" in everyday counting and queue[3] in Python code are two different positions, off by exactly one. Slicing (queue[1:3]) pulls out a range using that same 0-based counting, stopping one short of the second number, and .append() is how a list grows, always at the end.
