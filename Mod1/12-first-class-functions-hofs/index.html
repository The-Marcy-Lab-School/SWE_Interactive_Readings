The Route That Fell Off the List

~15 minutes Interactive No setup needed to read

1. A neighborhood that never got its groceries

Westside Pantry is a small food pantry that packs grocery boxes and drives them to people who can't come pick them up. Every Saturday the coordinator runs a short Python script that prints the busiest routes first, and volunteers claim routes from the top of the printed list.

The script copied the box counts into a second list called counts, sorted that list of numbers, then searched back through the routes to find the name that went with each number:

routes = [
    {'name': 'Hill Street', 'boxes': 12},
    {'name': 'Oak Row',     'boxes': 31},
    {'name': 'Pine Court',  'boxes': 12},
]

counts = []
for route in routes:
    counts.append(route['boxes'])

counts.sort(reverse=True)      # [31, 12, 12]

for count in counts:
    for route in routes:
        if route['boxes'] == count:
            print(route['name'])
            break

The print line runs once per count, so the script printed three lines:

Output — the counts version
Oak Row
Hill Street
Hill Street

Hill Street printed twice, and Pine Court never printed at all. Hill Street and Pine Court both have 12 boxes, and the search loop stops at the first route whose count matches, so the loop found Hill Street both times. Pine Court never reached the printed list, no volunteer claimed that route, and those boxes sat in the pantry all weekend.

The number 12 carries no route name with it. When the script searches the routes for a count of 12, the search finds Hill Street every time and never reaches Pine Court. Python can sort the routes themselves instead, which keeps every name attached to its own count. That fix rests on one fact: in Python a function is a value, the same way a number or a string is a value.

3. Three places a function can go

Print a function without calling it:

def say_hi():
    print("Hi")

print(say_hi)        # <function say_hi at 0x104fccd60>
print(type(say_hi))  # <class 'function'>

say_hi holds a value whose type is function, the way a variable called name holds a string. def say_hi(): is an assignment: the def statement builds a function and stores that function under the name say_hi.

Place one: a variable

A variable can hold any value, and a function is a value, so a second variable can hold this same function:

greet = say_hi   # no parentheses, so nothing runs and nothing is copied
greet()          # Hi

greet and say_hi are now two names for one function, and calling either name runs that one function.

Place two: a dictionary

The pantry runs a second script, a menu the coordinator picks jobs from. That menu started as a chain of branches, one per job:

if choice == "pack":
    pack_boxes()
elif choice == "label":
    print_labels()
elif choice == "route":
    assign_routes()

Every new job means typing another elif and retyping the comparison. Someone typed elif choice == "rout": last spring. Python does not complain about a comparison that comes out false, so the script raised no error; the coordinator picked that job, saw nothing happen, and assumed the script was slow.

A dictionary holds values, and a function is a value, so a dictionary can hold functions:

jobs = {
    "pack":  pack_boxes,
    "label": print_labels,
    "route": assign_routes,
}

jobs[choice]()

jobs[choice] looks up a function, and the () after that lookup calls whatever came back. One lookup line replaces the whole chain, and adding a new job takes one new line in the dictionary. A dictionary used this way is called a dispatch table.

You have already done this lookup without noticing. "abc".upper() finds the upper function stored inside the string and calls that function, exactly as jobs["pack"]() does. A function attached to a value like that is a method.

Place three: another function's argument list

A function can also be handed to another function, the same way a string can. The built-in sorted accepts a function:

names = ['Hill Street', 'Oak Row', 'Pine Court']
print(sorted(names, key=len))
# ['Oak Row', 'Pine Court', 'Hill Street']

len is written with no parentheses, so sorted receives the len function itself and calls len on each name. A function can sit in a variable, in a dictionary, and in another function's argument list, and a function can come back out of another function. That is what Functions are "first-class" values means.

Empty parentheses after a function's name mean Python runs that function on that line. A bare name stores the function or hands it over for something else to run later.

4. Writing a function that takes a function

The pantry prints three copies of every box label: one for the box, one for the folder, one for the driver. Two jobs in the Saturday script both do that:

for i in range(3):
    print_label()

for i in range(3):
    print_receipt()

The same loop is written twice, and the driver manifest will add a third copy. The pantry is also buying a printer that jams unless the script pauses a second between lines. That pause has to go inside every copy of the loop. Miss one copy, and that loop jams the printer on a Saturday morning.

Write the loop once instead, inside a function whose parameter is the job to run. One line of repeat is missing: the line that runs the job repeat was handed.

def repeat(callback, times):
    for i in range(times):
        ______________

repeat(print_label, 3)
repeat(print_receipt, 3)

Type the missing line.

Need a hint?

callback is a parameter holding a function. To run a function, write its name followed by parentheses. repeat has no argument to put inside them.

repeat never mentions labels or receipts. repeat calls whatever function it was handed, times times. The job that changes comes in from outside, so one copy of the loop serves every job, and you add the printer pause in one place. That is what makes repeat reusable.

repeat is a higher-order function (HOF): a function that accepts another function as an argument, returns a function, or does both. print_label, the function handed in, is the callback.

Hand over the function, not what it returned

Three rules decide what happens here. A function's name with no parentheses is the function itself, so writing the bare name hands the function over. The same name with parentheses runs the function right now, and the value that run produces is what gets handed over. A function with no return statement hands back None.

Python works out every argument before starting the call that argument belongs to, and the parentheses are part of the argument. So in repeat(print_label(), 3), print_label() runs first and prints one label; print_label has no return statement, so that call is worth None; and repeat gets handed that None. 5. sorted(), min(), and max() take a callback too

Python ships with higher-order functions of its own, and sorted() is the one you will reach for most. Its key parameter accepts a callback, and sorted calls that callback once on every item to get the value to compare. Each item stays whole and moves as one piece.

Section 3 used key=len that way. The same parameter fixes the bug in the counts version from section 1: write a function that pulls the box count out of one route, and hand that function to sorted:

def boxes(route):
    return route['boxes']

for route in sorted(routes, key=boxes, reverse=True):
    print(route['name'])

Here is what each version prints, with the same three routes:

Output — the counts version from section 1
Oak Row
Hill Street
Hill Street
Output — the boxes version
Oak Row
Hill Street
Pine Court

Pine Court is on the list now, and Hill Street prints once instead of twice. sorted compares the number boxes hands back but moves the whole dictionary, so a route's name never comes apart from its count, and the two routes tied at 12 boxes stay two separate routes. min() and max() accept key the same way, and both hand back the whole item rather than the number the callback produced for that item.

lambda, for a callback you use once

A callback you use once does not need a name, and a two-line def is a lot of typing for one line of work. lambda builds a small function in one expression, with no name:

biggest = max(routes, key=lambda route: route['boxes'])

The parameters go before the colon and one expression goes after the colon, and that expression's value is what the function hands back. A lambda has no room for a second line, so write a def as soon as a callback needs two.

Both blanks are the same parameter, spelled the same way in sorted, min, and max. Set that parameter to the bare name of a function that takes one item and hands back the value to compare. For the names, Python already has a built-in function that measures length.

6. A function that hands back another function

The coordinator is debugging the Saturday script and wants the terminal to say when each route starts posting and when that route is done. Six functions post things. By hand that is twelve print lines to paste in and twelve to take back out once the bug is found. Miss one, and volunteers keep seeing debug dashes every Saturday. Write the two print lines once instead, inside a function that takes the function to announce as its parameter:

def announce(func):
    def wrapper(route):
        print("--- posting ---")
        func(route)
        print("--- posted ---")
    return wrapper

def post(route):
    print(f"{route['name']}: {route['boxes']} boxes")

loud_post = announce(post)
print("ready")
loud_post(routes[0])

Three functions are involved — announce, wrapper, and post — and the three do not all run at the same time, so read the order carefully. announce(post) runs first. Inside announce, func holds the post function itself, because post was passed with no parentheses. announce then builds wrapper and hands wrapper back without calling it, so loud_post holds that wrapper, and nothing inside wrapper has run yet.

The call loud_post(routes[0]) runs two functions, not one. loud_post holds wrapper, so wrapper runs first and prints --- posting ---, then calls func(route). func is post, so post prints the route line. Then wrapper prints --- posted ---. Two of those three lines come from wrapper and one comes from post.

wrapper still has func even though announce finished two lines earlier. A function defined inside another function keeps access to the outer function's variables after that outer function returns, so wrapper carries func with it. post was never edited, and announce never mentions routes; the line loud_post = announce(post) is what joins the two. A function handed back this way is a wrapper, because that function wraps around the original.

The other three lines all come out of the single call loud_post(routes[0]): wrapper printed the first dashed line and the last one, and post printed the route line between them.

Python has a shorter spelling for handing post to announce: an @ on its own line, immediately before the definition.

@announce
def post(route):
    print(f"{route['name']}: {route['boxes']} boxes")

That is a decorator. The @announce line means exactly post = announce(post): a function was handed to another function, and what came back took the original's name.

7. Summary & reflection

A function is a value, so it can live in a variable, in a dictionary, or in another function's argument list, and it can be handed back out of a function. A function that takes or returns a function is a higher-order function, and the function you hand to it is the callback. Pass that callback by its bare name; parentheses run the callback on the spot and hand over its return value, which for a printing function is None. Pine Court showed up on the printed list again as soon as the Saturday script handed key=boxes to sorted and sorted the routes themselves.
