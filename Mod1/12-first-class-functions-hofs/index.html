The Route That Fell Off the List

~11 minutes Interactive No setup needed to read

1. A neighborhood that never got its groceries

Westside Pantry is a small food pantry that packs grocery boxes and drives them out to people who can't come pick them up. Every Saturday a volunteer runs a short Python script that prints the delivery routes in order, busiest route first, and volunteers claim them from the top of the printed list.

Here is what the script did. It pulled the box counts out into a second list, sorted that list of numbers, then walked back through the routes to find the name that went with each number:

routes = [
    {'name': 'Hill Street', 'boxes': 12},
    {'name': 'Oak Row',     'boxes': 31},
    {'name': 'Pine Court',  'boxes': 12},
]

counts = []
for route in routes:
    counts.append(route['boxes'])

counts.sort(reverse=True)      # [31, 12, 12]

for count in counts:
    for route in routes:
        if route['boxes'] == count:
            print(route['name'])
            break

It printed Oak Row, Hill Street, Hill Street. Pine Court has 12 boxes and Hill Street also has 12 boxes, and the search loop stops at the first route whose count matches, so it found Hill Street both times. Pine Court was never printed, so no volunteer ever claimed it, and those boxes sat in the pantry all weekend.

The bug comes from copying the numbers into their own list. A number on its own has no name attached to it, and matching it back by value cannot tell two routes with the same count apart. Python has a built-in way to sort the routes themselves, by a number it works out for each one, so no route is ever separated from its count. That tool is the subject of this reading, and it works because of something you may not have noticed yet about functions.

3. A function's name is a value you can hand to someone else

Try printing a function without calling it:

def say_hi():
    print("Hi")

print(say_hi)        # <function say_hi at 0x104fccd60>
print(type(say_hi))  # <class 'function'>

say_hi holds a value, the same way name would hold a string. That value's type happens to be function. In fact def say_hi(): is an assignment: it builds a function and stores it in the name say_hi. Because it is an ordinary value, you can copy it into a second variable, and the copy works exactly like the original:

greet = say_hi   # no parentheses, so this copies the function
greet()          # Hi

A function can also sit inside a dictionary, or get handed to another function as an argument, or get returned out of a function. All four of those abilities together are what people mean by Functions are "first-class" values. You have already used one of them without knowing it: "abc".upper() looks up a function stored inside the string and runs it. A function attached to a value like that is called a method.

The parentheses rule

Everything in this reading depends on one rule, so it is worth stating on its own before any code uses it:

A function's name written without parentheses is the function itself. Handing that name to something else hands over the function, and the receiver decides when to run it.

The same name with parentheses after it is an instruction to run the function right now. Python runs it on the spot and hands over whatever the function returned, which is almost never a function.

Python works out the value of every argument before it starts the call that argument belongs to. The parentheses are part of the argument, so a function call written inside an argument list has already finished running by the time the outer function begins. The pantry script now defines a function that pulls the box count out of one route.

def boxes(route):
    return route['boxes']

A volunteer writes sorted(routes, key=boxes()) and runs it. What happens?

4. sorted(), min(), and max() take a function

A higher-order function (HOF) is a function that accepts another function as an argument, returns a function, or does both. The function you hand in is the callback. Python ships with several higher-order functions, and sorted() is the one you will reach for most.

sorted() takes a key parameter. key accepts a callback, and sorted calls that callback once on every item to get the value it should compare. The items themselves stay whole and move as one piece:

def boxes(route):
    return route['boxes']

for route in sorted(routes, key=boxes, reverse=True):
    print(route['name'])

# Oak Row
# Hill Street
# Pine Court

Pine Court is on the list now. sorted compares the number that boxes hands back for each route, but it moves the whole dictionary, so a route's name can never come apart from its count. That is the fix for section 1's bug, and it took two lines.

The same key parameter works on the built-in functions min() and max(). Your turn:

Fill in the blank so this prints the name of the route with the most boxes.

def boxes(route):
    return route['boxes']

busiest = max(routes, ______________)
print(busiest['name'])   # Oak Row
Need a hint?

max has to be told which number to compare, and the parameter that carries that information is spelled the same way in sorted, min, and max. Set that parameter to the bare name of the function that pulls a count out of one route.

When lambda earns its place, and when it doesn't

Writing a four-line def for a callback you use once can feel like a lot of ceremony. lambda builds a small function in one expression, with no name:

oldest = max(users, key=lambda user: user['age'])

The parameters go before the colon, one expression goes after it, and that expression's value is what the function returns. There is no return keyword and no room for a second line.

Use lambda when the callback fits comfortably on one line and appears once. Everywhere else, use def. Here is the case people get wrong:

square = lambda x: x * x          # works, and still a worse choice
def square(x): return x * x       # does the same thing, better

Both lines build a function and store it in square, so lambda saves you nothing here. It costs you something, though. A function built with def knows its own name, and a function built with lambda reports its name as <lambda>. When that function raises an error, the traceback prints in <lambda>, and a traceback full of <lambda> lines gives you no way to tell which of your functions actually failed. So a lambda assigned to a variable is a worse def, not a shorter one.

5. A function that hands back another function

The pantry coordinator is debugging the Saturday script and wants the terminal to announce when each route gets posted and when it finishes. There are six functions that post things, and editing all six means pasting the same two print lines into each one, then picking all twelve lines back out when the debugging is done. Miss one and the terminal keeps printing dashes at a volunteer every Saturday.

Write the announcing as its own function instead. Its parameter is the function to announce:

def announce(func):
    def wrapper(route):
        print("--- posting ---")
        func(route)
        print("--- posted ---")
    return wrapper

def post(route):
    print(f"{route['name']}: {route['boxes']} boxes")

loud_post = announce(post)
print("ready")
loud_post(routes[0])

Three functions are involved and only one of them runs at the end, so read the order carefully. announce(post) runs first. Inside it, func holds the post function itself, because post was passed with no parentheses. announce then builds wrapper and returns it without calling it, and loud_post now holds that wrapper. Building a function prints nothing, so no dashes appear yet. The dashes wait until loud_post(routes[0]) actually runs the wrapper on the last line.

post was never edited and announce never mentions routes. The single line loud_post = announce(post) is what joins them. A function returned this way is a wrapper, because it wraps around the original.

Need a hint?

Find which line is the first one Python actually runs, rather than the first one written. loud_post = announce(post) builds a function and stores it, and building a function prints nothing at all, so look at what the next line does.

You will meet this pattern written a shorter way, with an @ on the line above a definition:

@announce
def post(route):
    print(f"{route['name']}: {route['boxes']} boxes")

That is a decorator, and it means exactly post = announce(post). Python comes with several of its own. Whenever you meet an @, read it as: a function was handed to another function, and what came back took the original's name.

6. Summary & reflection

Westside Pantry lost a route because sorting a list of bare numbers throws away which route each number belonged to; sorted(routes, key=boxes) fixes it by sorting the routes themselves and asking the boxes function for a number to compare. A function passed by its bare name is the function, ready for someone else to call, and the same name with parentheses is a call that has already happened.
