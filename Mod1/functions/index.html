The Discount Bug

Roast & Co., a small coffee shop, keeps a short Python script behind the counter that calculates each customer's total after their loyalty discount. When the shop raised that discount from 10% to 15%, whoever updated the script edited the formula in two places and missed a third — small-size orders quietly kept charging the old rate for weeks before a regular customer did the math out loud and complained. The fix wasn't more code. It was less: one function, defined once, called three times.

~13 minutes Interactive No setup needed to read

1. The bug that one function would have prevented

Here's the script Roast & Co. was actually running. Someone had written the loyalty-discount math once, for a small order, then copy-pasted that same block twice more for medium and large — changing only the price each time:

# small order
price = 3.50
total = price * 0.90
print(total)

# medium order
price = 4.25
total = price * 0.90
print(total)

# large order
price = 4.75
total = price * 0.90
print(total)

That worked fine until the shop raised the loyalty discount from 10% off to 15% off, meaning the multiplier needed to change from 0.90 (pay 90% of the price) to 0.85 (pay 85%). Someone opened the script, found the line, updated it, and then had to remember to find the same line two more times, in two more blocks that looked almost identical. They caught two of the three. The diagram below shows exactly where it went wrong, and what replacing all three blocks with one function actually looks like.

This pattern — the same logic, copy-pasted with a couple of numbers changed each time — is one of the most common ways bugs like Roast & Co.'s actually happen. Programmers have a name for the fix: DRY, short for "don't repeat yourself." A function is Python's basic tool for it. Write the logic once, then run it as many times as you need, with different inputs each time.

3. Writing your own function

Here's the function from the diagram above, on its own:

def order_total(price):
    return price * 0.85

Reading it line by line: def starts the definition, order_total is the name being given to this block of logic, and price in the parentheses is the parameter — a stand-in for whatever number gets passed in. The indented line underneath is the function's body: the actual math. Nothing runs yet just from typing this — a def block only runs the moment it gets called, by name, with an argument in the parentheses: order_total(4.25).

4. return vs. print: the mix-up that trips everyone up

The single most common beginner mistake with functions isn't the def line — it's assuming that print() inside a function makes a value available outside it. It doesn't. print() only displays something in the terminal; the value is gone the instant the function finishes. return is the only thing that hands a value back to be stored, reused, or passed into more code.

Only prints — the value is lost

def show_total(price):
    print(price * 0.85)

result = show_total(10)
print(result)

The terminal shows 8.5 once (from inside the function), then None — because show_total never handed anything back, so result was never actually set to 8.5.

Returns — the value survives

def get_total(price):
    return price * 0.85

result = get_total(10)
print(result)

The terminal shows 8.5 once — because result now actually holds the returned number, which print(result) is just displaying.

6. Summary & reflection

Roast & Co.'s bug happened because the same formula lived in three places at once, and updating it meant remembering to change all three. A function fixes that by definition: the logic exists exactly once, and every call — order_total(3.50), order_total(4.25), order_total(4.75) — reads from that same single copy. return is what makes the function's result usable afterward; print() only ever displays it in the moment.
