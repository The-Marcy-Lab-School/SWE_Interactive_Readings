The City That Wasn't in the Dictionary

~14 minutes Interactive No setup needed to read

1. The lookup that crashes

Weather apps get their numbers from a weather API (Application Programming Interface) — a service you can ask over the internet for data, and it answers back. Here's roughly what OpenWeatherMap's API actually sends when asked for Brooklyn's weather. It's real JSON (JavaScript Object Notation), the standard text format almost every API uses to send structured data back:

{
  "name": "Brooklyn",
  "main": {
    "temp": 71.6,
    "feels_like": 70.9,
    "humidity": 58
  },
  "weather": [
    {"description": "scattered clouds"}
  ]
}

Once Python parses that response, it's already a dictionary — a dict, Python's built-in way to store data as labeled key/value pairs instead of a numbered list. Curly braces hold the pairs, each key is a name in quotes, and each value is whatever data lives under that name. Pulling out one field is just response["name"], which returns "Brooklyn", or response["main"]["temp"], which returns 71.6. Square brackets plus the key name, and you have exactly the field you asked for. This works every time here because the API always includes these exact keys.

To avoid calling the API again every time someone re-checks a city, the tool keeps its own smaller dict of temperatures it has already fetched:

cached_temps = {
    "Brooklyn": 71.6,
    "Queens": 68.2,
    "Bronx": 69.5
}

That's the crash, exactly. Someone types "Manhattan," the code runs cached_temps["Manhattan"], and because "Manhattan" was never added as a key, Python raises an error right there:

>>> cached_temps["Manhattan"]
Traceback (most recent call last):
  File "weather_app.py", line 12, in <module>
KeyError: 'Manhattan'

Nothing after that line runs — not a friendly "sorry, no data for that city" message, nothing. The program simply stops. Square-bracket lookup is fine when you're sure the key is there. The problem is trusting it when you're not.

3. Writing a safe lookup

Compare the two ways of reading the exact same dict:

Square brackets — crashes on a missing key

cached_temps = {
    "Brooklyn": 71.6,
    "Queens": 68.2
}
temp = cached_temps["Manhattan"]
print(temp)

Line 4 raises KeyError: 'Manhattan' the moment it runs. print(temp) never executes at all.

.get() — falls back instead of crashing

cached_temps = {
    "Brooklyn": 71.6,
    "Queens": 68.2
}
temp = cached_temps.get("Manhattan", 0)
print(temp)

Line 4 returns 0 — the default supplied as the second argument — because "Manhattan" isn't a key. The program keeps going and prints 0.

6. Summary & reflection

A dict stores data as key/value pairs, which is exactly the shape of most real-world "look something up by name" data — a JSON API response included. dict["key"] is a fine way to read one when you're certain the key exists, but the instant it doesn't, Python raises a KeyError and the program stops cold. dict.get("key", default) asks the same question more carefully: give me this value if you have it, and this fallback if you don't — no crash either way.
