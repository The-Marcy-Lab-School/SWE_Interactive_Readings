The Discount Bug

~13 minutes Interactive No setup needed to read

1. The bug that one function would have prevented

Roast & Co. is a small coffee shop. Regulars get a loyalty discount on every drink, and one of the baristas wrote a short Python script to work out the discounted price. The barista wrote the math once for a small order, then copy-pasted those same three lines twice and changed the price each time.

# small order
price = 3.50
total = price * 0.90
print(total)

# medium order
price = 4.25
total = price * 0.90
print(total)

# large order
price = 4.75
total = price * 0.90
print(total)

Then the shop raised the loyalty discount from 10% off to 15% off. The multiplier had to change from 0.90 (pay 90% of the price) to 0.85 (pay 85%). Someone opened the script, updated the medium block and the large block, and missed the small one. Small orders kept ringing up at the old discount for three weeks, and nothing in the script looked broken.

Software engineers have a name for the rule this script breaks: Don't Repeat Yourself (DRY). The same three lines live in three places, so every change has to be made three times and every bug has to be fixed three times. A function is Python's tool for writing those lines once. 3. Writing a function, and what runs when

You have already called a function. print() is one. print(), len(), and type() are built-in functions: they come with Python, so you can call them without defining them first. A function you write yourself works the same way once Python has read its definition.

Here is the Roast & Co. math, written once as a function named order_total:

def order_total(price):
    """Return what a loyalty member pays for a drink."""
    return price * 0.85

def starts the definition. order_total is the name. price inside the parentheses is the parameter, a stand-in for a number the function does not have yet. A colon ends that first line, and every indented line under it is the function's body. The string on the first body line is a docstring: it says what the function does, and VS Code and the built-in help() function show it to whoever is about to call the function.

Calling the function by name runs its body. order_total(4.00) hands back 3.4.

Defining a function does not run it

Python reads a file from the top line to the bottom line. A def block is the exception. Running the def line creates the function and runs none of the lines inside it. Those lines run later, when a call names the function. Python jumps into the function, runs its body, and comes back to the line that made the call.

This script defines order_total halfway down the file and calls it twice at the end:

print("Opening Roast & Co.")

def order_total(price):
    return price * 0.85

print("Taking orders")

print(order_total(4.00))
print(order_total(10.00))

This script prints four lines. Click the four lines in the order the script prints them.

  • 8.5
  • Opening Roast & Co.
  • 3.4
  • Taking orders
Need a hint?

Creating a function with def prints nothing at all. Find the two print() calls that sit outside order_total first, in the order they are written. The two calls at the end run the function, and each one prints what order_total hands back.

4. Parameters, arguments, and calling with the wrong number

price in def order_total(price): is a parameter: a name the function uses for a value it does not have yet. 4.00 in order_total(4.00) is an argument: the real value handed over for that one call. Parameters are written in the definition. Arguments are written at the call.

A function can take more than one parameter. Roast & Co. prints one menu line per item:

def menu_line(item, price):
    print(item + " costs $" + str(price))

menu_line("Latte", 4.75)
menu_line("Scone", 3.25)

That script prints:

Latte costs $4.75
Scone costs $3.25

The arguments fill the parameters in order. The first argument becomes item and the second becomes price. Python also counts the arguments before it runs a single line of the body. Every parameter without a default value is required, so a call that is one argument short never gets inside the function at all.

You call menu_line("Latte") with one argument. What does Python do?

Default values and keyword arguments

A parameter can be given a default value, and then the caller is allowed to leave that argument out:

def menu_line(item, price, size="medium"):
    print(size + " " + item + " costs $" + str(price))

menu_line("Latte", 4.75)
menu_line("Latte", 5.25, "large")

That script prints:

medium Latte costs $4.75
large Latte costs $5.25

An argument can also be passed by keyword, which names the parameter it belongs to. Order stops mattering once you do: menu_line(price=4.75, item="Latte") prints medium Latte costs $4.75, the same line as the first call.

5. Turning repeated code into a function

Roast & Co. hands out loyalty points too, at 10 points per dollar spent. The script that works them out has the same shape as the discount script: three blocks, one value changing between them.

6. What return does, and what happens without it

A return statement does two things. It hands a value back to the place the call was made from, and it ends the function right there. No line after a return runs.

def order_total(price):
    return price * 0.85
    print("This line never runs.")

order_total(4.00) hands back 3.4 and the function ends on the return. Python never reaches that print().

A function with no return statement still produces a value: Python produces None for it. That trips up almost everyone the first time, because a print() inside a function looks like it is handing a value back. print() shows a value to the person at the terminal. return hands a value back to the program. Here are both versions of the same calculation:

The show_total version
prints, and returns nothing

def show_total(price):
    print(price * 0.85)

result = show_total(10.00)
print(result)

Prints:

8.5
None

The get_total version
returns the number

def get_total(price):
    return price * 0.85

result = get_total(10.00)
print(result)

Prints:

8.5

show_total prints 8.5 from inside the function and hands back nothing, so result holds None and the last line shows that None. get_total hands 8.5 back to the call, so result holds 8.5 and the last line shows the number.

A different function, greet, has the same shape as show_total:

def greet(name):
    print("Hello, " + name)

result = greet("Amir")
print(result)

7. Scope: where a name can be used

A variable's scope is the part of the program where its name can be used. Two scopes matter here. Global scope is the file, outside of any function, and a variable assigned there is reachable anywhere in that file. Local scope is the inside of a function, and a variable or parameter assigned there exists only while that function is running.

Here is a file named shop.py with one of each:

# shop.py
shop_name = "Roast & Co."

def order_total(price):
    rate = 0.85
    print(shop_name + " loyalty price:")
    return price * rate

print(order_total(4.00))
print(rate)

Running shop.py prints two lines and then crashes:

Roast & Co. loyalty price:
3.4
Traceback (most recent call last):
  File "shop.py", line 10, in <module>
    print(rate)
NameError: name 'rate' is not defined

The first two lines work because Python runs the file top to bottom and the broken line is last. Inside order_total, the line print(shop_name + " loyalty price:") uses a global name, which every line of the file is allowed to do. The last line tries the opposite. rate is assigned inside order_total, so rate is local and stops existing the moment order_total finishes. A NameError is what Python raises when a line uses a name that does not exist at the moment that line runs.

Someone adds one more line at the very bottom of shop.py. Check every name that new line is allowed to use without raising a NameError.

Need a hint?

Ask one question per name: was it assigned in the file outside every function, or inside order_total? One of the five was never assigned in shop.py at all, and Python still provides it.

8. Summary and reflection

A function gives one piece of logic one home. Define it once with def, give it parameters for the values that change, and call it as often as you need, which is what Don't Repeat Yourself (DRY) asks for. return hands a result back to the caller and ends the function, and a function without return hands back None. Names assigned inside a function are local to it, so a line outside the function that uses one raises a NameError.
