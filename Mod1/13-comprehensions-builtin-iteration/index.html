The Page That Went Up Empty

~20 minutes Interactive No setup needed to read

1. The Monday post that never went out

Maple Street Rescue is a small animal shelter that keeps about a hundred cats, dogs, and rabbits at a time. Every Monday a volunteer runs a short Python script that posts the pets who have been waiting longest to the shelter's website. A pet on that page gets phone calls. A pet left off it waits another week.

Each pet is a dictionary, and the dictionaries sit in a list called pets:

pets = [
    {'name': 'Biscuit', 'species': 'dog',
     'days_waiting': 96, 'adoptable': True},
    {'name': 'Pepper', 'species': 'cat',
     'days_waiting': 12, 'adoptable': True},
    {'name': 'Juniper', 'species': 'dog',
     'days_waiting': 210, 'adoptable': False},
    {'name': 'Mochi', 'species': 'cat',
     'days_waiting': 45, 'adoptable': True},
    {'name': 'Tilly', 'species': 'rabbit',
     'days_waiting': 61, 'adoptable': True},
]

One Monday the page went up with no pets on it. Here is the longest_waiting version of the script that produced that empty page:

def days(pet):
    return pet['days_waiting']

longest_waiting = pets.sort(key=days, reverse=True)

for pet in longest_waiting:
    print(pet['name'])

No names printed. The script stopped instead, on the line with the for:

Output — the longest_waiting version
Traceback (most recent call last):
  File "post_listings.py", line 19, in <module>
    for pet in longest_waiting:
               ^^^^^^^^^^^^^^^
TypeError: 'NoneType' object is not iterable

The .sort() method reorders the list it is called on and hands back nothing at all, so longest_waiting holds None. A for loop needs a list of values to walk through, and None is not one. Biscuit, 96 days in a kennel, stayed off the page for another week.

One word fixes that line, and you will write it yourself later in this reading. The rest of the script has a bigger problem: five separate hand-written loops, each doing a job Python already ships a tool for.

Code that spells out every step is called imperative. You control each move, and you type each move. Code that describes the result you want and lets an existing tool run the steps is called declarative. Python's list comprehensions and built-in list functions are how you write the declarative version.

3. The same new list, in one line

The shelter's script needs a list of just the pets' names. Three lines of the script do that: an empty list, a loop, and an .append() call. Here is that append version and the comprehension that replaces it, side by side:

The append version
names = []
for pet in pets:
    names.append(pet['name'])

print(names)
The comprehension version
names = [pet['name'] for pet in pets]

print(names)

Both print the same line:

Output — both versions
['Biscuit', 'Pepper', 'Juniper', 'Mochi', 'Tilly']

A list comprehension has three parts. The square brackets say a new list is coming back. The for clause says which list to walk through and what to call one element of it. The expression in front of the for says what to collect. Python runs that expression once per element, so the new list has exactly as many elements as the source list.

Read it from the for outward

A comprehension is written in the opposite order from the order it runs. Python cannot work out pet['name'] until it has a pet, and the for clause is what supplies one. So find the for first and read outward from there, in three steps.

Said out loud, [pet['name'] for pet in pets] is "for each pet in pets, take that pet's name, and collect the names in a new list." That takes a few seconds and tells you exactly what the line produces.

This comprehension collects every pet's wait in days. The expression is written for you and the for clause is missing.

waits = [pet['days_waiting'] ________________]

print(waits)
# [96, 12, 210, 45, 61]

Type the missing for clause.

Need a hint?

The expression pet['days_waiting'] uses the name pet, so the for clause has to give one element that exact name. The list it walks through is pets.

4. Keeping only some of them

Juniper has waited 210 days, longer than any other pet at Maple Street Rescue, and Juniper's record says 'adoptable': False because Juniper is on a medical hold. Posting Juniper brings in calls about a pet nobody can take home, and the volunteer has to turn every caller down. The listing page should show only the pets whose 'adoptable' value is True.

That is a filter: same elements, fewer of them. An if at the end of a comprehension keeps only the elements the test is true for. Here is the append version of the filter and the comprehension version together:

The append version
adoptable = []
for pet in pets:
    if pet['adoptable']:
        adoptable.append(pet)
The comprehension version
adoptable = [pet for pet in pets if pet['adoptable']]

for pet in adoptable:
    print(pet['name'])
Output — the comprehension version
Biscuit
Pepper
Mochi
Tilly

Two details carry this one. The expression in front of the for is just pet, so each whole dictionary comes through untouched, which is what the page needs: it prints a name and a wait from the same record. And the if runs once per pet on pet['adoptable'], a value that is already True or False, so no comparison is needed. if pet['adoptable'] == True gives the same four pets, it just asks a question whose answer was already sitting there.

A transform collects one new value per element, so its result is always as long as the source. A filter keeps only the elements that pass, so its result can be shorter: four pets out of five.

One comprehension can filter and transform at the same time. This one runs on the five pets in pets, with Juniper the only pet whose 'adoptable' value is False.

shown = [pet['name'] for pet in pets if pet['adoptable']]

print(shown)

When you want one match instead of all of them

A filtering comprehension hands back every element that passes. Sometimes a program needs the first one and nothing else, and for that a for loop with a return inside it does less work:

def first_urgent(pets, limit):
    for pet in pets:
        if pet['days_waiting'] > limit:
            return pet
    return None   # nothing passed the test

The return inside the loop is what makes first_urgent stop at the first match: the loop leaves immediately and never reads the rest of the list. The return None after the loop covers the case where no pet passed. Decide what that line hands back first, because every caller has to handle it.

5. Boiling a whole list down to one value

The shelter's board wants three numbers each month: how many pets are waiting, the longest wait, and the shortest. Python has a built-in function for each of those, and each one takes a list and gives back a single value:

waits = [pet['days_waiting'] for pet in pets]

print(len(waits))
print(max(waits))
print(min(waits))
print(sum(waits))
print(sum(waits) / len(waits))
Output
5
210
12
424
84.8

len() counts the elements, max() and min() find the largest and smallest, and sum() adds them all up. Dividing sum() by len() gives the average wait, 84.8 days.

When no built-in fits

The board also asks how many pets of each species the shelter is holding. No built-in function answers that, because the answer is not one number. It is a dictionary, and it has to be built up one pet at a time.

That shape is the accumulator pattern, the same counting variable you have already written in a for loop: create it before the loop, update it once per element, read it after. Here it starts as an empty dictionary, and .get(species, 0) supplies a count of 0 the first time a species shows up:

counts = {}
for pet in pets:
    species = pet['species']
    counts[species] = counts.get(species, 0) + 1

print(counts)
Output
{'dog': 2, 'cat': 2, 'rabbit': 1}

A comprehension cannot do this job. Curly braces and a key: value pair make a dictionary comprehension, which builds one entry per element and never looks at the entries it has already made:

waits_by_name = {pet['name']: pet['days_waiting']
                 for pet in adoptable}

print(waits_by_name)
Output
{'Biscuit': 96, 'Pepper': 12, 'Mochi': 45, 'Tilly': 61}

Each pet on the page is in there once, which is all that pairing needs. Counting is different: the second dog's count depends on the first dog's count, so each entry has to read what is already in the dictionary. The accumulator loop does that, and a comprehension does not.

One built-in call means one function name and a list, like sum(waits).

Select every job below that one built-in call already does for you.

Two more built-ins that stand in for a loop

any() and all() take a list of true-or-false values and give back one answer. any() is True when at least one element is true, and all() is True only when every element is:

print(any([pet['days_waiting'] > 180 for pet in pets]))
print(all([pet['adoptable'] for pet in pets]))
Output
True
False

One pet has waited more than 180 days, so any() is True. Juniper is not adoptable, so all() is False.

6. sorted() hands back a list, .sort() hands back nothing

Python has two ways to put a list in order, and they differ in what you get back. sorted() is a function that returns a new list and leaves the original where it was:

nums = [4, 2, 3, 5, 1]
ordered = sorted(nums)

print(ordered)
print(nums)
Output — the sorted version
[1, 2, 3, 4, 5]
[4, 2, 3, 5, 1]

.sort() is a list method that reorders the list in place. The original list changes, and the method returns nothing:

nums = [4, 2, 3, 5, 1]
nums.sort()

print(nums)
Output — the .sort() version
[1, 2, 3, 4, 5]

A volunteer assigns the result of .sort() to a variable and prints it.

nums = [4, 2, 3, 5, 1]
result = nums.sort()

print(result)

What does print(result) put on the screen?

Writing x = my_list.sort() and then wondering where the list went is one of the most common mistakes in Python, and it is the one that emptied the shelter's listing page. .append() and .reverse() behave the same way. .pop() does not: it changes the list and returns the element it removed:

letters = ['a', 'b', 'c']

print(letters.pop())
print(letters)
Output
c
['a', 'b']

So "methods that change a list return None" is not a rule you can lean on. Look up the method you are calling, or try it once in the interpreter.

key= picks what to compare, reverse=True flips the order

Both sorted() and .sort() take two optional keyword arguments. key= takes a callback, which is called once per element to produce the value to compare, and reverse=True puts the largest first. Dictionaries have no natural order, so sorted(pets) with no key= raises a TypeError. Sorting pets by their wait needs a callback that pulls that one number out.

Here is the longest_waiting version of the script that printed nothing, and the repaired version that uses sorted() instead:

The longest_waiting version — crashed
longest_waiting = pets.sort(key=days, reverse=True)

for pet in longest_waiting:
    print(pet['name'])
The repaired version
def days(pet):
    return pet['days_waiting']

adoptable = [pet for pet in pets if pet['adoptable']]
by_wait = sorted(adoptable, key=days, reverse=True)

for position, pet in enumerate(by_wait, start=1):
    waited = pet['days_waiting']
    print(f"{position}. {pet['name']}: {waited} days")
Output — the repaired version
1. Biscuit: 96 days
2. Tilly: 61 days
3. Mochi: 45 days
4. Pepper: 12 days

sorted() hands back a list, so the for loop has something to walk through. days is passed by its bare name, with no parentheses, so sorted receives the function and calls it once per pet. sorted compares the numbers days returns but moves the whole dictionary, which is why each line still has its own pet's name next to its own number. enumerate() supplies the position numbers, counting from 1.

Fill in both blanks. adoptable holds the four adoptable pets, and days returns a pet's 'days_waiting'.

    longest_first = sorted(adoptable, key=days, _________)

print([pet['name'] for pet in longest_first])
# ['Biscuit', 'Tilly', 'Mochi', 'Pepper']

  2. Alphabetical by name.

    def pet_name(pet):
    return pet['name']

by_name = sorted(adoptable, ______________)

print([pet['name'] for pet in by_name])
# ['Biscuit', 'Mochi', 'Pepper', 'Tilly']
Need a hint?

Both blanks are keyword arguments, written as a name, an equals sign, and a value. The first one asks for descending order. The second one needs the bare name of the function that pulls out the value to compare, with no parentheses after it.

7. Changing the loop without changing the listing

The volunteer wants to replace the append filter loop with the one-line comprehension. Both versions kept four pets out of five this week, but the real file holds 104 pets, and nobody wants to compare two printed lists of 104 names by eye. The pytest tests you already know how to write settle it instead.

Here is the function in src/listing.py, still written as a loop:

def adoptable_pets(pets):
    available = []
    for pet in pets:
        if pet['adoptable']:
            available.append(pet)
    return available

adoptable_pets is a pure function: it returns a new list and leaves the list it was handed alone. Testing a function that returns a list means testing two separate things, so tests/test_listing.py has two test functions:

from src.listing import adoptable_pets

PETS = [
    {'name': 'Biscuit', 'adoptable': True},
    {'name': 'Juniper', 'adoptable': False},
]


def test_adoptable_pets_keeps_the_adoptable_ones():
    """adoptable_pets - keeps only the adoptable pets"""
    kept = adoptable_pets(PETS)

    assert kept == [{'name': 'Biscuit', 'adoptable': True}]


def test_adoptable_pets_returns_a_new_list():
    """adoptable_pets - returns a new list"""
    kept = adoptable_pets(PETS)

    assert kept is not PETS
    assert PETS == [
        {'name': 'Biscuit', 'adoptable': True},
        {'name': 'Juniper', 'adoptable': False},
    ]

The two comparisons are different on purpose. == compares contents, so one list of dictionaries equals another holding the same dictionaries. is not compares identity, so kept is not PETS passes only when a genuinely different list came back. Run both tests with python3 -m pytest tests/test_listing.py:

Now swap the loop for the comprehension and run the same two tests again:

def adoptable_pets(pets):

Five lines became one, and the tests say the behavior is the same: same contents, still a new list. That is a refactor, and the passing tests are what made it a two-minute change instead of a gamble.

Writing the test first

Half of the shelter's records now arrive from a spreadsheet export, and that export writes days_waiting as text: '12' instead of 12. The monthly total crashes on those rows, because Python will not add a string to a number. The new rule the board agreed on is to add up the numbers and skip anything that is not one.

Test-driven development (TDD) writes the test for that rule before writing any code to satisfy it. The test says what the function should do, in a form that can be run:

def test_total_days_waiting_skips_text():
    """total_days_waiting - adds numbers, skips text"""
    rows = [
        {'name': 'Biscuit', 'days_waiting': 96},
        {'name': 'Pepper', 'days_waiting': '12'},
        {'name': 'Mochi', 'days_waiting': 45},
    ]
    assert total_days_waiting(rows) == 141

Run the tests now and the new one fails. A failing test is the point of this step, because it proves the test is actually checking something:

Output — red
collected 3 items

tests/test_listing.py ..F                            [100%]

    def total_days_waiting(pets):
>       return sum([pet['days_waiting'] for pet in pets])
E       TypeError: unsupported operand type(s) for +: 'int' and 'str'

=============== 1 failed, 2 passed in 0.02s ================

The traceback names the exact problem: sum() reached '12' and could not add a string to the running total. Keeping the text out of sum()'s way means knowing which values are numbers, and isinstance(value, type) answers that. It accepts a tuple of types, so one call covers whole numbers and decimals both:

def total_days_waiting(pets):
    numbers = [
        pet['days_waiting'] for pet in pets
        if isinstance(pet['days_waiting'], (int, float))
    ]
    return sum(numbers)
Output — green
collected 3 items

tests/test_listing.py ...                            [100%]

==================== 3 passed in 0.03s =====================

A filtering comprehension did the work, with isinstance as its test, and sum() added what came through. Red, then green: the test failed first, then the smallest change that could satisfy it made it pass.

8. Summary & reflection

A list comprehension builds a new list in one expression, and reading it from the for outward tells you what it produces. Add an if at the end and it keeps only the elements that pass. sum(), min(), max(), and len() turn a whole list into one value, and the accumulator loop covers the jobs they do not. sorted() gives you a new ordered list, while .sort() reorders in place and returns None — the reason Maple Street Rescue's page went up empty.
