The Gene That Became a Date

~13 minutes Interactive No setup needed to read

1. When a spreadsheet decided a gene was a date

Human genes have short official symbols: SEPT2, MARCH1, DEC1. In 2016 a team checked published genetics papers and found that about 20% of the ones with a gene list had at least one name changed by accident. SEPT2 had become the date "2-Sep". Nobody typed a date. Microsoft Excel saw text that looked date-shaped and rewrote it on its own, before anyone saved the file.

Excel was not being careless. Every value has to be treated as some kind of thing: text, a whole number, a date. When nothing says which kind, the program picks one for you. In 2020 the committee that names human genes renamed the worst offenders so software would stop confusing them, and a 2021 follow-up still found the problem in about 30% of newer papers. Python takes the other approach. You say what kind of thing a value is, and Python stops the program when an operation makes no sense for that kind instead of guessing.

Source: Ziemann, Eren & El-Osta, "Gene name errors are widespread in the scientific literature," Genome Biology (2016); Abeysooriya et al., PLOS Computational Biology (2021).

3. Every value has a type

A type is the category a value belongs to, and it decides what you are allowed to do with that value. You can do math on numbers and you can glue text together, and those are not the same job. Python has five basic types to start with.

The five basic Python data types, with the kind of real data each one usually holds.
TypeA value of that typeReal data it holds
str (string)"SEPT2", "@abc123"Text of any kind: usernames, chat messages, gene symbols, search queries
int (integer)50, -2Whole numbers: likes on a post, a game score, a count of items
float10.5, 0.99Numbers with a decimal point: prices, averages, percentages, timers
bool (boolean)True, FalseOne of two answers: dark mode on or off, logged in or not, won or lost
NoneNoneA value left empty on purpose: no result yet, nothing selected

Three more types hold other data or hold code: a list such as ["apple", "banana"], a dictionary such as {"name": "Alex", "age": 25}, and a function such as def greet(): print("Hi!"). Later lessons use all three.

Two values can look the same on screen and behave nothing alike, because only the type decides what an operator does to them. count = 5 and code = "5" both show a 5, but count holds an integer and code holds a string:

On numbers, + adds. On strings, + concatenates, which means it glues two pieces of text into one. Same symbol, different job, decided by the type. This is why a US ZIP code like "02134" has to be a str. Stored as an int it loses the leading zero and becomes 2134, a different and wrong ZIP code, and nothing warns you.

4. The six families of operators

An operator is a symbol that makes a new value out of values you already have. Python groups its operators into six families, and each family answers a different kind of question.

The six operator families, what each one does, and one example with the value it produces.
FamilyWhat it doesExample
Arithmetic operatorsCalculate a new value from numbers: +, -, *, /, //, %, **7 % 2 produces 1
Comparison operatorsCompare two values and produce a boolean: ==, !=, <, >, <=, >=5 >= 5 produces True
Logical operatorsCombine or reverse conditions: and, or, notTrue and False produces False
Membership operatorsCheck whether a value is inside a string, list, or dictionary: in, not in"a" in "apple" produces True
Identity operatorsCheck whether two names refer to the very same object: is, is notscore is None produces True when score holds None
Assignment operatorsStore a value in a variable: =, +=, -=, and the restlikes += 1 adds 1 to likes and stores the result

Two of these families surprise people the first time, so they are worth stating as rules.

Rule 1: + adds two numbers or joins two strings, and it has no third meaning. Two numbers of different kinds still add fine, because Python knows how to line them up: 5 + 2.5 produces 7.5, and True + 1 produces 2, since True counts as 1 and False counts as 0 in arithmetic. Mixing a string with a number is the one case + has no answer for. "3" + 5 stops the program with a TypeError, because Python will not guess whether you wanted the text "35" or the number 8.

Rule 2: comparison operators work on strings, and they compare character by character using each character's position in Python's character table. That table is not the dictionary order you learned in school. Every uppercase letter sits before every lowercase letter in it, so "B" > "A" is True and "apple" > "Banana" is also True, even though a dictionary would put Banana first.

5. Which operator goes first

Put several operators in one line and Python does not run them left to right. It runs them in a fixed order called operator precedence. Get that order wrong and the line still runs, still produces a number, and still prints with no error, so the only sign that anything is wrong is that the number is wrong.

Here is a line meant to convert 212 degrees Fahrenheit to 100 degrees Celsius:

fahrenheit = 212
celsius = fahrenheit - 32 * 5 / 9
print(celsius)  # 194.22222222222223

Python's order, highest first:

  1. Anything inside parentheses (), then function calls.
  2. Arithmetic. ** runs before *, /, //, %, which run before + and -. Operators at the same level run left to right.
  3. Comparison: <, <=, >, >=, ==, !=.
  4. Logical: not first, then and, then or.
  5. Assignment with =, last of all.

Walk the Celsius line through that order. 32 * 5 runs first and produces 160, because * outranks -. 160 / 9 is at the same level as *, so it goes next, left to right, and produces about 17.8. Then 212 - 17.8 produces about 194.2. Assignment runs last and stores that in celsius. Python followed its own rules at every step. The formula needs the subtraction to happen first, and nothing in that line said so.

Parentheses outrank everything, so a pair of them is how you move an operation to the front of the line:

fahrenheit = 212
celsius = (fahrenheit - 32) * 5 / 9
print(celsius)  # 100.0

Now 212 - 32 produces 180, then 180 * 5 produces 900, then 900 / 9 produces 100.0. The two versions differ at the very first step, and everything after that follows from which operator got to go first.

A different conversion, same problem. This line is meant to turn a price in dollars into cents after a $2 discount, so price = 10 should produce 800 cents. It produces -190 instead.

price = 10
cents = price - 2 * 100
print(cents)  # -190

Which version of the cents line produces 800?

Need a hint?

Parentheses only help when they change which operator runs first. Work out each of the three lines by hand with price = 10, and notice that two of them produce the same answer as the line with no parentheses at all.

6. Variables: assign, reassign, reference

A variable is a name for a piece of data. Naming data is what lets a program do one calculation, keep the answer, and build the next calculation on top of it. All the values a program is holding right now are its state, and variables are how that state is stored.

There are three things you do with a variable, and each one has a word:

# Assign: create the variable count and give it the value 0
count = 0

# Reference: use the value the variable is holding
print(f"count starts at {count}")

# Reassign: give the same variable a new value
count = 1
print(f"count is now {count}")

That script prints:

count starts at 0
count is now 1

You can reference a variable's current value inside the line that reassigns it. The right side runs first, all the way to a single value, and only then does = store it:

count = 0
count = count + 1   # the right side produces 1. count becomes 1
count += 1          # same work, written shorter. count becomes 2
count += 3          # any amount works. count becomes 5
count *= 2          # -=, *= and /= work the same way. count becomes 10

+= is called augmented assignment. count += 1 and count = count + 1 do exactly the same work, and you will see the short form far more often, because counting something up is one of the most common things a program does.

What does this script print? The second line combines augmented assignment with two operators, so precedence decides the answer.

msg = "hello"
msg += "world" + "!" * 3
print(msg)
Need a hint?

* runs before +, and the whole right side finishes before += stores anything. * on a string repeats that string, the same way + on two strings glues them together.

Naming the variable

Python's convention is snake_case: lowercase words joined by underscores. The name should say what the data is, because a reader who cannot tell what a variable holds has to trace the whole program to find out.

# Unclear what these numbers count
numbers = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

# Clear
days_in_each_month = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

# Descriptive, but hard to read
daysineachmonth = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

# Readable, but not Python's convention
daysInEachMonth = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

One name is written differently on purpose. A variable whose value should never change is written in ALL_CAPS, and every Python programmer reads those capitals as "do not reassign me". A variable like that is called a constant.

MAX_GUESSES = 5

# Python does not stop you from doing this, so the capitals are a message to
# the next person reading the code, not a lock.
MAX_GUESSES = 10

Check every name that is a good snake_case name for a value your program will change as it runs.

7. Summary and reflection

Every value in Python has a type, and the type decides what each operator does to it, which is why + adds two numbers and glues two strings but refuses a string and a number. When several operators share a line, precedence sets the order, and parentheses are how you change it. A variable gives a value a name so the rest of the program can reference it, reassign it, or update it in place with +=.
